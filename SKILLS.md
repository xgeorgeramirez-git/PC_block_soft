# Карта скиллов проекта PC_block_soft

Каждый загруженный скилл занимает контекст до конца чата, поэтому набор задаёт планировщик, а исполнитель вехи грузит только «Skills to load» из шапки плана вехи. Скилл сверх списка — запись Ruling в ledger вехи с причиной.

## Всегда

| Скилл | Зачем |
|---|---|
| dev-methodology | Порядок работы: план вехи, TDD, серия по лестнице R0–R4, ревью свежим субагентом, приёмка, закрытие вехи, уроки |
| git-guru | Коммиты (Conventional Commits, описание на русском в повелительном наклонении), тег версии на закрытии вехи |

## По признаку задачи

| Признак задачи | Скилл |
|---|---|
| Новый или изменённый экран, флоу, окно (экран блокировки, значок, мини-панель, окно родителя, статистика) | uiux-design — в режиме «рабочее приложение» по ТЗ 8.0 (сдержанно, без декора на экранах с данными) |
| Готовы снимки экранов вехи (Фаза 7) или UX-сценарий в плане (Фаза 2) | usability-heuristics — аудит по UX-сценарию и снимкам; визуальный проход делает агент `visual-reviewer` |
| Ревью диффа интерфейса (Фаза 6) | web-design-guidelines — доступность, фокус, формы, клавиатура |
| Веха добавляет пользовательский функционал | in-app-guidance — только после гейт-вопроса заказчику «внедряем ли подсказки и обучение» и ответа «да» |

Визуальная приёмка — агент `visual-reviewer` (`.claude/agents/visual-reviewer.md`, модель haiku), не скилл. Если агента нет в списке — обычный субагент с `model: "haiku"` и тем же поручением.

## НЕ грузить и почему

| Скилл | Почему |
|---|---|
| frontend-design | Пересекается с uiux-design; стиль уже задан ТЗ 8.0 |
| xlsx, docx, pptx, pdf | Выгрузки не нужны (D-25), документов программа не делает |
| deep-research | Исследований в вехах нет; справки — точечный WebSearch |
| golang-how-to и профильные Go-скиллы | Не установлены; правила Go и Wails — `references/gotchas.md` методики и `CLAUDE.md` |
| google-workspace, nano-banana, morning и др. | Чужие домены |
