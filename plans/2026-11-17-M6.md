# План вехи M6 «Защита от обхода» (версия 0.7.0)

**Goal:** служба замечает перевод часов (при включении и во время работы), смену часового пояса и вход в безопасном режиме и пишет это обходом в журнал без блокировки; системные инструменты, открытые ребёнком, закрываются с плашкой и записью (D-86).

**Architecture:** вся логика — в `internal/service` на стандартной библиотеке и портах `Config` (монотонный счётчик, часовой пояс, признак безопасного режима); Windows-адаптеры — в `internal/service/winhost` (реестр). Распознавание системного инструмента по пути — чистая функция в `internal/programs`. Наблюдатель процессов (`watch.go`) решает судьбу инструмента до вердикта «система».

**Tech Stack:** Go 1.27 (stdlib в service/programs), `golang.org/x/sys/windows/registry` в winhost, PowerShell-приёмка `tools/accept`.

**ТЗ:** 1.30 — R17 (а, б, г, е), FR-28…FR-30, S23, S24, S53, S54; D-41, D-86, D-87.

## Global Constraints

- Реакция на обход — только журнал, экран не блокируется, время не отключается (D-41); исключение — системный инструмент закрывается (D-86).
- Ребёнок-администратор — без записей обхода (R1, `bypassIn` уже отсекает).
- «На экране ребёнка» = сеанс с `childID != 0` и `!ss.offScreen()` (не отключён и не заблокирован).
- Порог часов 120 с (строго больше — обход); пояс — не позже 2 с (обслуживание раз в секунду).
- Тексты родителю на «вы», ребёнку на «ты», без длинных тире (`tools/scan_ui_texts.py`), без техники.
- Новые виды событий журнала не нужны: обход — `core.EvBypass` с подробностями `detail`, `subtype`; подтипы: `clock_changed`, `clock_back_boot`, `tz_changed`, `safe_mode`, `system_tool`.
- Тестовый режим: наблюдатель трогает только `Test.WatchDir` (RM3-8); инструменты в тестовом режиме — копии в WatchDir с именами инструментов.
- Self-hosted runner заказчика не привязывать; блокировки — только в CI.

## Review Focus

1. Ложные срабатывания часов: синхронизация Windows (< 120 с), сон и гибернация (стена и монотонный счётчик идут вместе), перезапуск службы (граница при включении), часы ядра в тестовом режиме (сверка — по настоящим часам `RealNow`, не по `Clock`).
2. Приписка обхода не тому: пояс или часы сменил родитель в своём сеансе, сеанс ребёнка заблокирован или отключён, ребёнок-администратор (R1) — записи обхода нет.
3. Системный инструмент, запущенный игрой или установщиком (родитель — не Проводник, не инструмент и не брокер Магазина, ввод старый), не закрывается и не становится «незнакомой программой» (класс уроков PL-18, PL-19, R13).
4. Повторы журнала: страж повторяет, наблюдатель видит процесс в каждом проходе — одна запись на попытку (`bypassLogWindow`, `watchOnce`), граница «последний раз служба работала» пишется не чаще раза в минуту.
5. Ошибки портов (реестр не читается) не валят обслуживание и не пишут обход: только журнал работы с ограничителем (`logRate`).

## UX-сценарий (ребёнок)

Ребёнок жмёт Win+R, пишет `cmd`, Enter → окно мигнуло и закрылось → внизу справа плашка «Программа «Командная строка» недоступна» (как у запрещённой программы, без кнопок) → работа продолжается, экран не блокируется. Родитель в журнале видит «Миша: попытка обойти защиту. Открыта командная строка, она закрыта».

## Итог ревью плана (Issues Found → внесено)

- Critical: стена — через `Round(0)` (у `time.Now` есть монотонная часть, `Sub` считал бы по ней, и дрейф всегда ноль).
- Пояс сравнивается по ключу, стандартному смещению `Bias` и `DynamicDaylightTimeDisabled`, а не по `ActiveTimeBias`: переход на летнее время не смена пояса.
- Быстрый запуск Windows 11 — это гибернация служебного сеанса, `Start` не вызывается: скачок назад, когда на экране нет ни одного сеанса, пишется как при включении (`clock_back_boot`). ТЗ R17а дополнено.
- Монотонное время Go на Windows — `_INTERRUPT_TIME` (`runtime/time_windows.h`), сон в нём есть: проверено по исходникам.
- Родитель-инструмент распознаётся по настоящим путям всегда; WatchDir расширяет только сам процесс. Терминал ручным считается только при родителе Проводнике или инструменте (ветка брокера Магазина для него не действует): иначе две записи на одно открытие cmd и закрытие консоли игры.
- R17д: обычной учётке Windows служба недоступна, инструменты для неё (mmc, `sc`) закрываются по (г); `sc.exe` добавлен в список. ТЗ уточнено.
- Повтор записи обхода — по подробности в окне 60 с для каждой (память по подробностям), а не одной последней.
- Безопасный режим — флаг в `sessState`, ставится при появлении ребёнка в сеансе.

## Задачи

### T1. Перевод часов во время работы и при включении (R17а, D-87)

Files: Create `internal/service/clockguard.go`, `internal/service/clockguard_test.go`; Modify `internal/service/service.go` (Config `Mono func() time.Duration`; поля службы `clockWall time.Time`, `clockMono time.Duration`, `clockSaved time.Time`; `Start` — проверка при включении; `Stop` — сохранить границу), `internal/service/loop.go` (Housekeep: `s.guard("clock", nil, func() { s.checkClock(real) })`).

- Config.Mono nil → монотонный счётчик процесса: `start := time.Now(); func() time.Duration { return time.Since(start) }` (Go на Windows считает его по времени прерываний, сон и гибернация в нём есть).
- `checkClock(real)`: `mono := s.cfg.Mono()`; первый вызов — запомнить; иначе `drift := real.Sub(prevWall) - (mono - prevMono)` (стена через `Round(0)` не нужна: real из RealNow; в тестах — поддельные значения). `|drift| > clockJumpLimit (120 с)` → `onClockJump(expected := prevWall.Add(mono-prevMono), real)`. Запомнить; граница `clock.last_seen_ms` пишется, если `real.Sub(clockSaved) >= time.Minute` или после скачка или `clockSaved` в будущем.
- `onClockJump`: сеанс ребёнка на экране (`activeChildSession()`) → `bypassIn(ss, clockChangedDetail(expected, real), "clock_changed", real)`; иначе `Logf("часы компьютера переведены с … на …, на экране не ребёнок: обходом не считается")`.
- `Start`: `checkBootClock(real)` до `s.started = true`: граница есть и `real < last - 120 с` → `s.journal.Write(0, core.EvBypass, {"detail": bootBackDetail(last, real), "subtype": "clock_back_boot"})`; затем граница = real.
- Тексты (на «вы» не нужно — безличные): `«Часы компьютера переведены: было 17.11 14:05, стало 17.11 16:20»`; `«Часы компьютера ушли назад: служба последний раз работала 17.11 в 21:40, после включения на часах 17.11 в 20:40»`. Время — в `s.cfg.Loc`.
- Тесты (поддельные RealNow и Mono): +30 с без записи; сон 8 ч (стена и счётчик +8 ч) без записи; +10 мин при ребёнке на экране — одна запись `bypass` у ребёнка с обоими временами; −10 мин — запись; сеанс заблокирован — нет записи; ребёнок-администратор — нет; при включении граница +1 ч впереди — запись без ребёнка `clock_back_boot`; граница на 60 с впереди — нет; граница позади на 9 ч — нет; граница пишется не чаще раза в минуту.

Expected: `go test -race -count=1 -run 'Clock' ./internal/service/` — PASS.

### T2. Смена часового пояса (R17б, S23)

Files: Create `internal/service/tzguard.go`, `tzguard_test.go`; Modify `service.go` (Config `TimeZone func() (TimeZoneInfo, error)`; поля `tz TimeZoneInfo`, `tzKnown bool`), `loop.go` (Housekeep `s.guard("tz", …)`).

- `type TimeZoneInfo struct{ Key, Display string; BiasMin int }`; равенство по Key и BiasMin.
- Ошибка — `logRate("tz", …)`, состояние не меняется. Первый успешный — запомнить. Изменение → сеанс ребёнка на экране → `bypassIn(ss, "Часовой пояс изменён: был «X», стал «Y»", "tz_changed", real)`; иначе журнал работы. Display пустой → Key.
- Тесты: пояс сменился при ребёнке на экране — запись; при родителе на экране — нет; ошибка чтения — нет записи и нет паники; без смены — ничего; смена только перехода на летнее (Bias) — запись.
