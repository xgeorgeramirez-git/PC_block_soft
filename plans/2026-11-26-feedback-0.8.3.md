# Фидбек-раунд 0.8.3: окно сообщения со стикером и звуком (FB-28)

Goal: родитель на телефоне выбирает к сообщению стикер (74 анимированных) и звук (5 своих mp3 или «Без звука», с прослушиванием); у ребёнка окно «Сообщение от родителя» нового вида (вариант Б макета) с движущимся стикером и выбранным звуком.
Architecture: протокол 5а получает необязательные `sticker`/`sound`; служба несёт их до стража без толкования; страж знает свой встроенный набор и сам подменяет неизвестное (без стикера, звук 1). Окно сообщения становится layered-окном (предумноженная альфа, `UpdateLayeredWindow`, образец `internal/systray/card_render.go` + `card_windows.go`): карточка, тень и стикер с нахлёстом рисуются чистым Go в BGRA-буфер, текст — шрифтом системы; кадры стикера — тем же спрайтом, что промокод (300 px, 30 кадров/с, все 74 встроены). Звук — `sound.PlayMessage(n)` из встроенных wav. Android: экран отправки вместо диалога, сетка стикеров (PNG первого кадра, выбранный — Lottie), выбор звука с прослушиванием (MediaPlayer из assets).
Tech Stack: Go 1.27 (`internal/remote`, `internal/service`, `internal/ipc`, `internal/guard`, `internal/sound`, `tools/remote-phone`), Python + Playwright (`tools/sticker-frames.py`), ffmpeg (`tools/sound-wav.sh`), PowerShell (`tools/accept/`), Kotlin + Compose (`android/`).
ТЗ: 2.7 — FR-41, NFR-4 (≤ 70 МБ), 8.0 п. 3, 4, 9; 8.2 «Сообщение от родителя»; S57, S60; D-101; протокол 1.4, раздел 5а. Макет: https://claude.ai/artifact/CVXTibjNSFyQpfRs45LD1R (вариант Б — `VariantB`, поверх блокировки — вид Б, не А).

Skills to load: dev-methodology, git-guru; uiux-design (T4, T5); web-design-guidelines — на ревью UI-диффа не применяется (интерфейс не веб: Win32 и Compose), ревьюер смотрит доступность по смыслу (размеры касания ≥ 48 dp, подписи кнопок для TalkBack).

- Сеть — только `internal/remote` (NFR-1). Протокол: новые поля необязательные; старый компьютер их игнорирует (`json.Unmarshal` без DisallowUnknownFields — не менять); старый телефон их не шлёт → без стикера, звук 1.
- `remote.Note`: сырые поля `StickerRaw json.RawMessage json:"sticker,omitempty"`, `SoundRaw json.RawMessage json:"sound,omitempty"` (неверный JSON-тип не должен валить `json.Unmarshal` в `checkSigned` → `bad_sig`, ревью I-1) и разобранные `Sticker string json:"-"`, `Sound int json:"-"`. `CheckNote` после подписи: `sticker` — нет поля или строка ровно из 3 цифр ASCII; `sound` — нет поля, или целое 0…99 без дробной части (`2.0`, `2.5`, `"2"`, `null` — `ErrCodeRange`); нет поля `sound` → 1 (протокол 5а). Дальше по ipc — простое `int`.
- `noteRec` (очередь `remote.notes` в настройках) — `Sticker string json:"sticker,omitempty"`, `Sound *int json:"sound,omitempty"`: записи 0.8.2 без поля после обновления → звук 1 при выдаче в `deliverNotes` (ревью I-6); в `ApplyNote` тоже nil-защита.
- Подмена неизвестного — **только в страже** (он знает встроенный набор): стикер не встроен (`stickerFrames(n) == 0`) → без стикера; звук не встроен (`!sound.HasMessage(n)`) и не 0 → 1. Служба и журнал хранят то, что прислал телефон.
- Журнал родителя не меняется: «Миша: сообщение с телефона: «текст»».
- Звуки: `assets/sounds/message/N.mp3` → `internal/sound/message/N.wav` (PCM 16 бит, 44,1 кГц, стерео, без метаданных, bitexact), sha256 каждого mp3 — `internal/sound/message/N.mp3.sha256`; длина wav = длина mp3 ± 0,1 с; **без обрезки** (D-101). Набор звуков — по файлам, не константа в коде: новый `N.mp3` + перегенерация = новый звук.
- Стикеры: все 74 из `assets/stickers/*.tgs` → `internal/guard/assets/stickers/NNN.png` + `frames.json` генератором `tools/sticker-frames.py` (300 px, 30 кадров/с, как промокод, D-84). Набор стикеров стража = ключи `frames.json`.
- Установщик ≤ 70 МБ (NFR-4): шаг `windows.yml` «Размер установщика» — порог 73400320 и тексты.
- Вид окна — ТЗ 8.2 «Сообщение от родителя» дословно: стикер ~170 px при 100 % (низкий экран — до 96 px), нижняя часть стикера заходит на карточку (нахлёст 56 px при 100 %, пропорционально размеру стикера); карточка `#EEF4FC`, рамка 2 px `#2F6DB5`, скругление 20 px, тень; по центру: «Сообщение от родителя» синим 18 px полужирный, текст 28 px полужирный `#1B1F23` (длинный — мельче, не меньше 14 px, целиком, с переводами строк), кнопка «Понял» во всю ширину внутреннего поля, высота 56 px, скругление 10 px, `#2F6DB5`, белый текст 22 px. Без стикера — карточка без картинки и без верхнего нахлёста. Ширина карточки 520 px при 100 % (узкий/длинный — правила `noteWidths` как сейчас). Синий — только это окно (8.0 п. 3).
- Окно целиком (стикер + карточка + тень) — не выше 55 % рабочей области (было 40 % для плашки без стикера; Ruling FB28-1 ниже); поверх экрана блокировки не перекрывает его заголовок и кнопки (существующие `NoteLock`/`ShiftUp`/`ShiftDown`). Тень входит в прямоугольник окна (`NoteLayout.Shadow`, `Place` = окно с тенью): её пиксели с альфой > 0 ловят клики, поэтому окно с тенью не пересекает `NoteLock` (ревью I-2). Кнопка «Понял» — скругление 6 px (ТЗ 8.0 п. 1; на макете 10 px, разница незаметна).
- Стикер сообщения движется по кругу, пока окно видно (у промокода — одно проигрывание, не трогать). Анимации Windows выключены (`still`) — первый кадр, тикер не запускается. Размер стикера `min(Scaled(170, dpi), StickerFramePx)`, низкий экран — не меньше `min(Scaled(96, dpi), StickerFramePx)`. Окно может висеть часами (`showSec` = 0): каждый кадр обновляется только прямоугольник стикера (`UpdateLayeredWindowIndirect` с `prcDirty`), основа карточки (тень, фон, текст, кнопка) собирается один раз на смену раскладки. Звук — один раз на показ (`NoteSoundDue`, как сейчас), номер — из сообщения; «Без звука» — ни одного вызова плеера.
- Память стража (NFR-5 ≤ 40 МБ): полоса кадров промокода и сообщения не держатся вместе в BGRA. Сообщение держит палитровый спрайт (1 байт на точку) и переводит в BGRA только текущий кадр; всё освобождается при закрытии окна. Бюджет сообщения: кадры × 300² (спрайт; 90 кадров — 8,1 млн байт) + 2 кадра BGRA + DIB окна + основа карточки (при 150 % около 3 МБ каждая) ≤ 16 МБ; тест считает удерживаемые буферы по этой формуле для 90 кадров при 150 % (ревью I-3).
- Звук — один цикл `soundLoop`, одна очередь: элемент очереди несёт вид звука (предупреждение или сообщение) и номер; PlaySoundW никогда не играет два звука одновременно; проверка «плеер задан» — для своего вида (ревью I-5). Стражу задаются оба плеера: `SetSoundPlayers(warning func() bool, message func(n int) bool)`.
- Тестовый режим стража (`GuardStateReply`): `noteSticker` (номер показанного стикера, "" — без), `noteFrame` (номер текущего кадра), в `ShownSound` — `noteSound` (номер сыгранного звука). Только в тестовом режиме, как `Sounds`.
- Тексты: ребёнку на «ты», родителю на «вы», без длинных тире (скан `tools/scan_ui_texts.py`); Android-строки — в `res/values/strings.xml`.
- Android: `lottie-compose` (com.airbnb.android, версия 6.x последняя стабильная), `.tgs` распаковывается `GZIPInputStream` в JSON и отдаётся `LottieCompositionSpec.JsonString` (не полагаться на распознавание gzip библиотекой). Assets: `sourceSets["main"].assets.srcDir("../../assets")` (стикеры, звуки сообщения); `android.yml` — триггер и на `assets/**`. Последний звук и срок запоминаются (`NoteBook`), стикер в новом сообщении — «Без стикера». Сборка только в CI.
- Go nil-слайс → `[]T{}`; локальные Go-тесты — командой из `CLAUDE.md` («Локальные тесты Go без сети»); Windows-код — только CI.

## Rulings

- **FB28-1:** предел высоты окна сообщения — 55 % рабочей области (было 40 %): стикер 170 px не помещается в 40 % при высоте 720 вместе с двумя строками текста и кнопкой. Цена ошибки: на низком экране окно закрывает середину экрана блокировки — ловится тестом раскладки (экраны S60) и `TestNoteWindowOverLockFits` (порог там же, 55 %).
- **FB28-2:** S60 «1280×720» проверяется тестом раскладки, а не сменой разрешения раннера (ТЗ S60 уже так сформулирован).
- **FB28-4:** длины звуков в тесте — из файла `internal/sound/message/durations.json`, который пишет `tools/sound-message-wav.sh` по `ffprobe` исходных mp3 (не константа в тесте: новый звук добавляется без правки кода, D-101).
- **FB28-3:** вид поверх экрана блокировки — вариант Б (заказчик выбрал Б; артборд «поверх блокировки» на макете нарисован в виде А только для показа положения).
