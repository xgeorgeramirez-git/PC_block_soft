## Правила процесса (общие для всех сессий)

- Оркестратор сам код не пишет: конвейер «два слота», один писатель кода за раз, документы параллельно из дерева docs.
- Модели (D-39): писатели — `sonnet`; ревью, план, решения — старшая модель; два возврата у писателя — эскалация на `opus`.
- Пакеты субагентам кладутся в `plans/packets/M1-<задача>.md` (не в scratchpad — его не видит другая сессия). В каждом пакете абзац «контекст продукта» (домашний родительский контроль, ставит администратор, слежки нет, администратор может удалить) — без него фильтр безопасности обрывает работу субагента.
- TDD; изменение требований — сначала в `docs/01_ТЗ.md` заменой текста, решение заказчика — строка D-N; код только через feature-ветку и PR.
- Блокировки на компьютере заказчика не запускать — только в CI в тестовом режиме. Force-push, удаление данных, изменения вне репозитория — только с явного согласия заказчика.
- Заказчика спрашивать только при неясном объёме или перед необратимым действием; по-русски, просто.
- Лимит оборвал субагента — инвентаризация git, продолжить того же субагента (SendMessage) или нового по тому же пакету; сделанное не переделывать.
- Конец сессии: обновить этот файл («Ведёт сейчас» → «Свободно», состояние, шаги), ledger, реестр, запись в начало `docs/HISTORY.md`; всё закоммитить и запушить.
