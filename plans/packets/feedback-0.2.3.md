## Контекст продукта

PC_block_soft — домашняя программа родительского контроля для Windows 11 (аналог Microsoft Family Safety). Её ставит родитель-администратор на семейный компьютер. Служба считает экранное время в детских учётках и по исчерпании лимита показывает экран «время вышло»; родитель снимает его паролем. Слежки нет; администратор в любой момент может удалить программу. Журнал родителя показывает, что происходило за день. Эта задача убирает ложные записи из журнала родителя.

Отвечай по-русски. Методика dev-methodology (Фаза 9, TDD: сначала падающий тест).

## 1. Замечания и корневая причина

План раунда: `plans/2026-10-26-feedback-0.2.3.md` (на main; прочитай `git show origin/main:plans/2026-10-26-feedback-0.2.3.md`). ТЗ `docs/01_ТЗ.md`: R17 (последнее предложение: штатное завершение сеанса — выход, смена пользователя, выключение, сон — обходом не считается и записью не сопровождается), FR-27 (перезапуск не позже 3 с), R22, D-43.

**FB-1.** При выключении, перезагрузке компьютера и выходе из детской учётки в журнал родителя пишется «попытка обойти защиту» («Защита программы была остановлена», «Окно программы было закрыто не кнопкой окна»), иногда дважды. Лог службы заказчика (версия 0.2.2):
```
2026/10/26 12:15:44 Процесс guard в сеансе 1 завершился без сообщения интерфейса
2026/10/26 12:15:44 Окно mystats в сеансе 1 завершилось без сообщения интерфейса
2026/10/26 12:15:45 Процесс guard в сеансе 1 завершился без сообщения интерфейса
2026/10/26 12:15:45 Окно mystats в сеансе 1 завершилось без сообщения интерфейса
2026/10/26 12:15:46 Служба остановлена
2026/10/25 20:57:55 Процесс guard в сеансе 1 завершился без сообщения интерфейса   (выход из учётки)
```
Причина (сверена по коду main): значок при конце сеанса шлёт `TrayClosing` (`internal/service/sessions.go` trayClosing), а страж в `internal/guard/run_windows.go` hostProc на `WM_ENDSESSION` только вызывает PostQuitMessage — службе ничего не сообщает; окна Wails тоже. `procDied` и `superviseWindow` в `internal/service/sessions.go` сразу вызывают `bypassIn`. `OnSession(SessionLogoff)` (помечает `expected`) и остановка службы приходят позже. При выключении страж перезапускается (`nextTry = real`) и снова закрывается — вторая запись.

**FB-2.** `internal/service/journaltext.go:46` — `fmt.Sprintf("доп. время +%d мин", ...)` при отрицательных минутах даёт «+-60». Нужно «доп. время −60 мин» (знак U+2212, как в подменном бэкенде `frontend/src/__mocks__/backend.ts` и в CHANGELOG 0.2.1); убедись, что скан текстов CI его пропускает.

## 2. Что сделать

1. **Сообщение стража о штатном закрытии.** Новая команда канала `GuardClosing` в `internal/ipc/commands.go` (+ список команд, `contract.json`, тесты контракта) по образцу `TrayClosing`; в таблице прав службы — только вид клиента «страж»; обработчик помечает `ss.guard.expected = true`, только если PID собеседника совпадает с PID стража, запущенного службой (как `trayClosing`). Страж вызывает её при `WM_QUERYENDSESSION` и при `WM_ENDSESSION` с `wParam != 0` — до выхода, с коротким таймаутом (не задерживать конец сеанса; ошибку канала игнорировать). Вызов вынеси в тестируемую логику (контроллер) и покрой юнит-тестом; Win32-часть проверит CI.
2. **Отложенное решение в службе.** В `procDied` (страж и значок) и `superviseWindow` для детского сеанса: перезапуск — как сейчас (FR-27), а вместо немедленного `bypassIn` — запись в ожидание (сеанс, SID, подробность, подтип, момент) на `bypassGrace = 5 * time.Second` по реальному времени (`real`, не часы ядра). Повторная гибель того же процесса в пределах ожидания не создаёт второе ожидание. Ожидание снимается без записи: событие `SessionLogoff`/`SessionDisconnect` этого сеанса; сеанс пропал из списка Windows или сменил SID в `syncSessions`; остановка или выключение службы (`Shutdown`/stop — все ожидания снимаются). В обычном такте ожидания старше `bypassGrace` при живом сеансе того же SID превращаются в запись (`bypassIn` как раньше). Строку лога «…завершился без сообщения интерфейса» оставь (диагностика), запись в журнал — только по итогу ожидания; при снятии ожидания — строка лога в подробном режиме (`vlogf`).
3. **FB-2** — текст отрицательных минут.
4. **Тестовая команда для приёмки.** В тестовом режиме (`TestGuard`, только при ключе реестра TestMode) — действие «конец сеанса»: страж проходит тот же путь, что при `WM_ENDSESSION` (сообщает `GuardClosing` и завершается). Найди, как устроены действия `TestGuard` (`internal/guard`, `internal/service`), и добавь по образцу.
5. **Приёмка** `tools/accept/`: новый сценарий `fb1-*.ps1` — страж в детском сеансе получает тестовый «конец сеанса» → через 10 с в журнале нет записи об обходе (`ListEvents`), страж запущен заново. Регресс: S5 и S27 (и любые сценарии, где ждут запись об обходе) — ожидание записи теперь до 10 с; проверь, что они по-прежнему находят запись при настоящем принудительном завершении. Подключи FB1 к значению `scenario` в `.github/workflows/windows.yml` по образцу соседних (как подключали S12/S13). Строка FB1 — в `docs/06_Приёмка.md`.
6. **Версия 0.2.3**: `internal/version/version.go` и `wails.json` productVersion вместе; `CHANGELOG.md` раздел `## 0.2.3 — <дата>` простыми словами для родителя (две строки: выключение, выход и смена пользователя больше не попадают в журнал как попытка обхода; убавленное время пишется как «−60 мин»). «Что нового» Помощника не добавлять (Ruling в плане).

## 3. Тесты (RED прежде кода; ожидания — литералами)

Служба (поддельные запуск и часы, по образцу существующих тестов `sessions`):
- страж умер → в течение 5 с остановка службы → записей обхода 0;
- страж умер → в течение 5 с `OnSession(SessionLogoff)` того сеанса → 0;
- страж умер → сеанс исчез из `Sessions()` → 0;
- страж умер → сеанс жив 5+ с → ровно 1 запись «Защита программы была остановлена», страж перезапущен не позже следующего такта;
- страж умер, перезапущен, умер снова в пределах 5 с → выключение → 0; без выключения → 1;
- `GuardClosing` от PID запущенного стража → гибель без записи; от другого PID → игнор, через 5 с запись есть;
- окно mystats умерло + выключение → 0; сеанс жив → 1 запись «Окно программы было закрыто не кнопкой окна» и окно открыто заново;
- взрослый сеанс — записей нет (как раньше).
Журнал: −60 → «…: доп. время −60 мин»; +15 → «…: доп. время +15 мин».
