## 1. Требования (дословно из ТЗ 1.8, прочитай R3, R4, R5, R8, R9 в `docs/01_ТЗ.md` и G4, G5, G12 в `docs/04_Эталоны_учёта.md`)

- R5: остаток игр = лимит игр дня + доп. время за сегодня − игры за сегодня. Игры входят и в общее время. По исчерпании лимита игр закрываются и не запускаются только программы категории «Игры»; остальное продолжает работать. Лимит игр «без лимита» (nil) — игры ограничены только общим лимитом; 0 — игры сегодня нельзя.
- R3/R4: учёба не входит в общее время (`Accumulator.Tick` уже так считает: Study → только StudyS).
- R8: режим «Блокировать экран» (по умолчанию): при исчерпании общего времени или в запретный интервал показывается экран блокировки, программы «Игры» закрываются, остальные окна остаются под экраном. Режим «Оставить только учёбу»: в тех же случаях экрана блокировки НЕТ, закрываются и не запускаются все программы, кроме «Учёба» и «Системное».
- R9: пороги 30/15/5/1, предупреждение о конце лимита игр, «если сейчас на переднем плане игра»; порог взводится только если до события строго больше его минут (PL-14); один порог — одно уведомление.
- R11: пауза снимает все ограничения (в том числе закрытие игр и режим «только учёба»); учёт идёт.

## 2. Решения оркестратора (Ruling — не пересматривать без эскалации)

- **C-1 Типы.** `DayLimit` получает `GamesMin *int` (nil — игры без отдельного лимита; `0` — нельзя). `Rules` получает `EndMode EndMode`; `type EndMode int` с константами `EndBlock` (ноль, по умолчанию) и `EndStudyOnly`; `func (m EndMode) String() string` → `"lock"` / `"study_only"` и `func EndModeFromString(s string) EndMode` (неизвестное → `EndBlock`).
- **C-2 Остаток игр.** В `day.go` рядом с `RemainingTotalS`: `RemainingGamesS(limit DayLimit, extraMin, gamesS int) (remaining int, unlimited bool)`, остаток не меньше 0.
- **C-3 Решение.** В `Decision` добавить: `GamesRemainingS int`, `GamesLimitS int` (лимит игр с доп. временем, 0 без лимита), `GamesUnlimited bool`, `CloseGames bool`, `StudyOnly bool`, `CloseReason string`. Методы: `func (d Decision) Allows(cat Category) bool` (Lock ≠ LockNone → false; StudyOnly → только `CatStudy`; CloseGames и `CatGames` → false; иначе true) и `func (d Decision) DeniedText(cat Category) string` (текст для журнала/плашки запуска: при StudyOnly — константа `StudyOnlyDeniedText = "Закрыто: время вышло, доступна только учёба"`, при CloseGames и играх — `GamesDeniedText = "Закрыто: время на игры на сегодня закончилось"`, иначе пусто).
- **C-4 Когда что.** Порядок `decide`: пауза (ничего не закрыто) → запретный интервал → время вышло → иначе проверка лимита игр.
  - Запретный интервал / время вышло, `EndBlock`: как сейчас (`Lock`, `Status`, `Reason`, `Until`) плюс `CloseGames = true`.
  - Запретный интервал / время вышло, `EndStudyOnly`: `Lock = LockNone`, `StudyOnly = true`, `Status` как сейчас (StatusForbidden / StatusTimeUp — красный), `Until` как сейчас, `CloseReason = StudyOnlyPlateText = "Время вышло. Сейчас доступна только учёба"` (для запретного интервала — `StudyOnlyForbiddenPlateText = "Сейчас нельзя пользоваться компьютером. Доступна только учёба"`).
  - Иначе, если лимит игр есть и остаток игр ≤ 0: `CloseGames = true`, `CloseReason = GamesOverPlateText = "Время на игры на сегодня закончилось"`; экрана блокировки нет, `Status` по общему остатку как сейчас.
  - Поля `GamesRemainingS`, `GamesLimitS`, `GamesUnlimited` заполняются всегда (при `Rules.Broken` — `GamesUnlimited = true`, закрытия нет: R18).
- **C-5 Учёт запрещённой секунды.** `Engine.Tick` передаёт в `Accumulator.Tick` флаг `blocked = d.Lock != LockNone || !d.Allows(CategoryOf(s))` — секунда программы, которой сейчас нельзя, не засчитывается (иначе G5/G12 разъезжаются на секунды закрытия). Сигнатуру `Accumulator.Tick(now, s, blocked bool)` оставь (переименуй параметр `lockShown` → `blocked`, поправь комментарий).
- **C-6 Предупреждения игр.** Новый `WarnGames` (после `WarnPauseEnd`; `String()` → `"games"`). В `Engine` второй набор порогов `gwarn warnings` для остатка игр: `rearm()` взводит его на `GamesRemainingS` (limited только если лимит игр есть, нет паузы и правила не `Broken`), событие `WarnGames`. В `decide` (ветка без блокировки) после общих порогов: игровой порог срабатывает по своему остатку; если сработали оба — уходит тот, у которого меньше секунд до события, при равенстве — общий (экран/блокировка важнее); второй всё равно гасится. Игровой порог, сработавший при `gamesDelta > deltaS` общего ближайшего события (игровое событие не ближайшее: общий лимит кончится раньше), в `Decision` не попадает, но гасится. `WarningS` — секунды до события сработавшего. Пороги игр, как и общие, перевзводятся при доп. времени, копилке, промокоде, паузе, новых правилах, смене суток (там же, где вызывается `rearm`); срабатывание на границе + `SetRules` в ту же секунду не даёт повтор (PL-14).
- **C-8 Категория «Системное» ядру не нужна.** Ядро знает 4 категории; программы класса «система» служба передаёт как `CatOther` и сама никогда не закрывает (R3: «Системное» → «Прочее»). `Allows` относится к категории секунды переднего плана и к решению «можно ли запустить обычную программу такой категории»; исключения «система» делает служба.
- **C-9 Что засчитано.** В `Decision` добавить `Counted bool` и `CountedCat Category`: `Engine.Tick` после `Accumulator.Tick` заполняет их (секунда засчитана и в какую категорию, `CategoryOf(s)`), чтобы служба вела `usage_daily`, не дублируя R2. Они не попадают в `Current()` (там нулевые).
- **C-10 Игровые пороги только при игре на переднем плане (R9).** Игровой порог срабатывает на тике, где `CategoryOf(s) == CatGames`; иначе он остаётся взведённым (но гасится при блокировке/закрытии игр). Поле передаётся в `decide` (например, через поле `Engine.fg`, выставляемое `Tick` до `decide`; `Current()` порогов не гасит).
- **C-7 Режим окончания и расписание не теряются.** `Engine.SetRules` принимает `Rules` целиком (с `EndMode`); больше нигде ядро не пересобирает `Rules` по частям.

## 4. Review Focus (классы входов/отказов)

1. Дубли уведомлений (PL-13/PL-14): общий и игровой порог одновременно; перевзвод при `AddExtra`/`SpendBonus`/`RedeemPromoMinutes`/`ReduceExtra`/`ClearExtra`/`Pause`/`SetNoForbiddenToday`/`SetRules`/смене суток — везде, где вызывается `rearm`, игровые пороги перевзводятся тоже.
2. Остаток игр и доп. время: `ReduceExtra` убавляет и лимит игр; остаток не отрицательный; `GamesLimitS` при `GamesMin=0` и доп. времени.
3. Секунда у границы: тик ровно в момент исчерпания (`rem == 0`): решение до учёта секунды (порядок тика не меняется).
4. Пауза и `Broken`: никаких закрытий; `Decision.Allows` истинно для всех.
5. Сутки (PL-15 класс): `Current()` при смене суток без тика показывает новый день, игры и закрытия не переносятся.
6. Совместимость: `Decision` с нулевыми новыми полями у старого кода означает «ничего не закрывать».
