## 2. Ruling оркестратора

- **S-1 Порт.** В `ports.go`:
  ```go
  type ProcInfo struct { PID uint32; Stamp uint64; SessionID uint32; Path string; PathOK bool }
  type ProcessWatcher interface {
      // List возвращает процессы сеанса sessionID; нечитаемый путь — PathOK=false.
      List(sessionID uint32) ([]ProcInfo, error)
      // Kill завершает процесс, если PID и Stamp всё ещё совпадают (ручка открыта при проверке); true — завершён.
      Kill(p ProcInfo) bool
  }
  ```
  Поле в `service.Config` (`Watcher ProcessWatcher`, nil — наблюдение выключено), фейк `fakeWatcher` в `fakes_test.go` (процессы по сеансам, журнал завершений, настраиваемые ошибки, «защищённые» процессы, которые Kill не берёт).
- **S-2 Цикл наблюдения (RM3-11).** Отдельный метод `Service.Watch(real time.Time)` + собственный тикер в `RunLoop` (`watchEvery = 250ms` по настоящим часам, не зависит от `TickInterval`/`ClockSpeed`); под `s.mu` берётся только моментальный снимок нужных данных (сеансы ребёнка, решение `Decision` каждого ребёнка, классификатор, `programsReady`), сам `List`/`Kill` — **вне** `s.mu`. Для каждого сеанса ребёнка: `List(sessionID)`; для каждого процесса:
  1. `!PathOK`, неизвестный/родительский сеанс (R19), администратор (R1), `Path` в классе «система» → **не трогать** (нечитаемые пишутся в журнал работы с ограничением частоты, не в журнал родителя).
  2. Новый процесс (ключ `PID+Stamp`, кэш пути/вердикта до смерти процесса): `Classify(Path, fingerprint)` (отпечаток — `FileMeta`, только для путей вне доверенных и только если у программы есть сохранённый отпечаток).
  3. `VerdictUnknown` → Kill, `AddPendingAttempt` (имя из имени файла, издатель/описание из `FileMeta`), событие `program_pending` (не чаще раза в 60 с на путь и ребёнка), плашка `BlockedUnknown` («Программа «X» ждёт разрешения родителя», `CanAsk: true`).
  4. `VerdictForbidden` → Kill, событие `program_forbidden_try` (нарушение R13, экран НЕ блокируется, D-33), плашка `BlockedForbidden` («Программа «X» запрещена родителем»).
  5. `VerdictAllow(cat)`: если `!decision.Allows(cat)` и (`cat == games` при `CloseGames` либо любая категория кроме `study` при `StudyOnly`) → Kill, плашка (`BlockedGamesOver` «Время на игры на сегодня закончилось» / `BlockedStudyOnly` «Время вышло. Сейчас доступна только учёба»), событие `program_closed_games` / `program_closed_study_only` (не нарушение). Плашка одна на путь не чаще раза в 5 с.
  6. Каждый тик (не только новые процессы): если `Decision.CloseGames`/`StudyOnly` стало истинным, уже работающие процессы закрываются тем же правилом (включение запрета закрывает запущенное).
  Если `!programsReady()` или `Watcher == nil` — наблюдатель ничего не закрывает (RM3-10, R18). Режим паузы (R11) и `Rules.Broken`: ничего не закрывать. `Decision.Lock != LockNone` в режиме `EndBlock`: закрывать только игры (R8), остальное остаётся под экраном.
  Процесс, закрытый наблюдателем, **не** считается нарушением и не вызывает записи «обход защиты»; убедись, что гибель процесса PC Block невозможна (класс «система» по `InstallDir`).
- **S-3 Категория секунды (RM3-1, RM3-7).** `sampleFor` определяет `Foreground` не по строке стража, а по `Classify(ForegroundPath)`: `Allow(games|study|other)` → соответствующая категория; `System`/`Unknown`/пустой путь → `CatOther`. (Страж в M3 присылает путь; `Foreground`-строка от стража игнорируется, кроме `video_social` — M4.) Неизвестная программа не должна успеть засчитаться как игра.
- **S-4 Учёт по программам (RM3-6).** `childState` держит накопитель `usage map[usageKey]int` в памяти: после `Tick` ядра, если `d.Counted` и `d.CountedCat` ∈ {games, study, other} и путь известен — `+1` секунда на `(категория, путь в нижнем регистре)`. Сброс в хранилище: вместе с `day_state` — через `Store.SaveDayAndUsage` в `saveDay` (по `DueSave`, смене суток — записи привязаны к дню накопления; при ошибке записи накопитель не очищается).
- **S-5 Плашки.** Отправка стражу — очередью `guardCmd[session]` как `noticeGuards`: команда `GuardCmdBlocked` с `Plate`. Ребёнку в отключённом сеансе плашки не шлются. Тексты — константы в одном месте (рядом с `textBlocked…`), на «ты».
- **S-6 Игровые предупреждения.** Они уже проходят через `afterDecision` (ядро T2 + контракт T3a). Проверь: `GuardWarning{Event:"games", Text}` попадает в очередь предупреждений и в `Status` значка; тест на цепочку «Tick → предупреждение 30/15/5/1 игр».
- **S-7 Журнал.** Виды и тексты — из T3b (`program_*`). Запись через `s.journal.Write(child.ID, kind, details)`; повторы одного и того же события на один путь — не чаще раза в 60 с (ограничитель).
- **S-8 Тестовый режим (RM3-8).** `ParseTestMode`/`TestModeValueNames` получают `WatchDir` (путь, нормализованный); в тестовом режиме наблюдатель обрабатывает только процессы, чей `Path` внутри `WatchDir` (иначе пропускает). Остальное поведение — как в боевом режиме. Тест.

## 3. Задачи (RED → GREEN → мутации → коммит)

T4a.1 Порт, фейк, каркас `Watch` + тикер в `RunLoop` (тест: тикер не зависит от `TickInterval`).
T4a.2 Вердикты 3–6 (Unknown, Forbidden, Allow/запрет, включение запрета закрывает запущенное). Таблица тестов с фейковым сеансом ребёнка, `Decision` из настоящего ядра на фейковых часах.
T4a.3 «Не трогать»: система, нечитаемый путь, неизвестный и родительский сеанс, администратор, `!programsReady`, пауза, `Broken`, `Watcher == nil`; процесс PC Block (`InstallDir`) — никогда.
T4a.4 `sampleFor` по пути (S-3) и накопитель `usage` + `SaveDayAndUsage` (S-4), включая смену суток и ошибку записи.
T4a.5 Плашки (S-5), игровые предупреждения (S-6), журнал (S-7), тестовый режим (S-8).
T4a.6 Регресс штатных завершений (PL-5, PL-13): выход из сеанса/смена пользователя/остановка службы при работе наблюдателя не пишет «обход защиты» (существующие `fb5_test.go`, `fb1`-тесты зелёные + новый: закрытие игры наблюдателем не создаёт записей `bypass`).

Мутации (в Evidence с именами упавших тестов): убрать ветку «система» → падает тест процесса `InstallDir`; поменять `Allows` на всегда-true → тест лимита игр; убрать `programsReady` → тест первого старта после обновления; убрать `Stamp` из ключа кэша → тест повторного использования PID; `Kill` под `s.mu` (искусственно) → тест, что вызов канала не блокируется во время `Kill` (фейк с задержкой).

## 4. Review Focus

1. NFR-6: между запуском процесса и `Kill` не более одного периода опроса (250 мс) + время `Kill`; тест на фейковых часах реального тикера допустим.
2. PL-9: `PathOK=false` или `SessionID` неизвестен → «не трогать»; PL-7/8: передний план нечитаем → `CatOther`, секунды идут как «Прочее».
3. PL-13: гибель окон/WebView2/значка по вине наблюдателя невозможна (класс «система»); закрытие не пишется обходом.
4. PL-16/PL-1: ограничители журнала и плашек не прячут первое событие; фейки и состояния чистятся в `t.Cleanup`.
5. Гонки: `go test -race` на всех новых тестах, `Watch` и `Tick`/`Handle` одновременно.
6. Сутки (PL-15): накопитель использования привязан к дню; смена суток в момент сброса не смешивает дни.
7. Две программы одновременно (игра + учёба в разных окнах): при лимите игр закрыта только игра; секунды идут по переднему плану, как прежде (R2/R3).

- **Д-1 Нечитаемый отпечаток (эскалация T3b №1).** Для решения родителя по программе вне доверенных каталогов (у записи есть отпечаток) пустой/нечитаемый отпечаток при запуске = `VerdictUnknown` (снова «Ждёт решения», `WasCategory` сохраняется), а не «оставить решение»: иначе ребёнок закрывает SYSTEM доступ к свойствам своего файла и подменяет exe. Это закрытие одной программы, не блокировка компьютера (R18 не нарушается). Поправь `Classifier` и тесты T3b; мутация: вернуть «пустой отпечаток разрешает» → падает новый тест.
- **Д-2 Сканирование вне `s.mu` (эскалация №2).** `ensurePrograms`/повтор в `Housekeep`/`hScanPrograms` вызывают `Scanner.Scan()` вне блокировки службы (снимок данных под `s.mu`, скан без неё, запись результата под `s.mu`; повторный скан не запускается, пока идёт предыдущий). Тест: фейковый сканер с задержкой, вызов канала во время скана отвечает без ожидания.
- **Д-3 Microsoft Store (эскалация №3).** `WindowsApps` НЕ класс «система»: ребёнок может сам ставить приложения из Store, иначе игра из Store не закрывалась бы никогда. Правило: `<ProgramFiles>\windowsapps\` — доверенный каталог (писать туда может только система); корень приложения — **семейство пакета** без версии: из `name_version_arch_resourceid_publisherid` → `name__publisherid` (например, `microsoft.minecraftuwp_1.21.0.0_x64__8wekyb3d8bbwe` → `microsoft.minecraftuwp__8wekyb3d8bbwe`), чтобы обновление версии не делало приложение «незнакомым»; снимок при старте (`Scanner`, T4b) включает установленные пакеты как «Прочее», каталог игр по имени exe (`minecraft.windows.exe` и т.п.) и по семейству (`microsoft.minecraftuwp`, `microsoft.minecraftjavaedition`, `roblox`) действует и здесь; новые пакеты после снимка → «Ждут решения». Системные приложения оболочки лежат в `C:\Windows\SystemApps` — это `SystemRoot`, они «система». Обнови `programs` и тесты (таблица: калькулятор с новой версией → тот же корень; Minecraft → Игры по каталогу; неизвестный пакет → Unknown; `c:\users\kid\windowsapps\x.exe` → Unknown).
