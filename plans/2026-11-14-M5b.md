# План вехи M5b «Автозагрузка» и стикеры промокода — версия 0.6.0

**Goal:** родитель видит и выключает автозагрузку каждого ребёнка (новые записи сами выключены и ждут решения); ребёнок при вводе промокода видит большой анимированный стикер заказчика и случайную надпись.

**Architecture:** чистая логика автозагрузки (разбор команд, заданий, StartupApproved, сверка «найдено/было») — новый пакет `internal/startup` на стандартной библиотеке; чтение и запись Windows — порт `StartupSource` в службе и его реализация в `internal/service/winhost/startup_windows.go` рядом с `policy_windows.go` (`withHive`, `hiveLoaded`); решения — таблица `startup_items` (миграция 011); выключенная общая запись и «страховка» для своих — правило наблюдателя процессов (закрыть без плашки и нарушения, как R13). Стикеры: в окне ребёнка — проигрыватель lottie-web (MIT, встроен файлом), на экране блокировки — заранее отрисованные кадры (спрайт PNG на стикер, `//go:embed`), выбор стикера и надписи — чистые функции в Go и TS.

**Tech Stack:** Go 1.27 (служба, страж, x/sys/windows/registry, schtasks.exe), SQLite (modernc), React + TypeScript + Vite, Playwright (снимки, CI), lottie-web 5.13.0 (`lottie_light.min.js`), Python + Playwright + Chrome (генерация кадров, только в песочнице разработчика).

**ТЗ:** 1.26 — FR-39, 8.3.11, S50, таблица `startup_items` (раздел 4); R26, FR-35, 8.2.3 п.3, 8.2.6 п.11, S36, S52 (D-83); раздел 9 строка M5b. Решения D-76, D-80, D-83. Бэклог B-60, B-67, B-68.

**Skills to load:** dev-methodology, git-guru; uiux-design (T5, T8, T9 — экраны); usability-heuristics (визуальный проход, Фаза 7); web-design-guidelines — только ревью UI-диффа. in-app-guidance не грузить (D-56).

## UX-сценарий

**Родитель, автозагрузка (8.3.11).** Дети → Миша → вкладка «Автозагрузка» (рядом с «Лимиты», «Запретные часы», «Когда время вышло», «Перерыв на отдых»). Видит три блока: «Ждут решения» (только если есть; новые записи, выключатель выключен), «Учётка Миши», «Для всех пользователей». Строка: значок вида записи, название, издатель (если есть), «откуда», выключатель. Нажал выключатель → он сразу меняется (без кнопки «Сохранить»), под списком сообщение «Будет запускаться при входе Миши» / «Не будет запускаться при входе Миши»; запись из «Ждут решения» переходит в свой блок. Ошибка службы — выключатель возвращается, сообщение «Не удалось сохранить. Попробуйте ещё раз». Пусто — «При входе Миши ничего не запускается». Список обновляется при открытии вкладки и после каждого действия; подпись «Проверено в 18:40» (время последней проверки службы).

**Ребёнок, промокод в «Моя статистика» (8.2.6 п.11).** Бонусы → «Ввести промокод» → «Ввести». Верный: справа от поля (на узком окне — под полем) стикер 160×160 проигрывается один раз и остаётся на последнем кадре, рядом крупная надпись «Ура! +30 минут»; остаток сразу больше. Неверный: стикер неудачи и надпись «Хм, код не подходит. Посмотри внимательнее», код в поле остаётся. Начал печатать новый код — стикер и надпись исчезают. Анимации выключены — стикер стоит.

**Ребёнок, промокод на экране блокировки (8.2.3 п.3).** «Ввести промокод» → поле → «Ввести». Неверный: над полем стикер неудачи (≈200 px при 100 %) и надпись, поле с кодом остаётся. Верный: панель с полем заменяется стикером удачи и надписью «Есть! Тебе +30 минут» по центру; через одно проигрывание (≤ 3 с) экран исчезает; плашка «Добавлено N минут» после этого не показывается (надпись уже сказала). В запретный интервал: стикер удачи и надпись, экран остаётся, ниже прежнее пояснение «Их можно будет потратить…».

## Rulings плана

- **RM5b-1 Источники (FR-39).** Свои: `HKU\<SID>\Software\Microsoft\Windows\CurrentVersion\Run` и `RunOnce`; папка `<профиль>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup`; задания Планировщика с триггером «при входе» этого пользователя (`<LogonTrigger><UserId>` = SID или имя ребёнка); приложения магазина — ключи `HKU\<SID>\Software\Classes\Local Settings\Software\Microsoft\Windows\CurrentVersion\AppModel\SystemAppData\<PackageFamily>\<TaskId>` со значением `State`. Общие: `HKLM\...\Run`, `HKLM\...\RunOnce`, `HKLM\SOFTWARE\WOW6432Node\...\Run`, папка `%ProgramData%\Microsoft\Windows\Start Menu\Programs\StartUp`, задания с `LogonTrigger` без `UserId`. Задания читаются из XML-файлов `%WINDIR%\System32\Tasks\**` (UTF-16, служба — система), без COM; выключаются `schtasks.exe /Change /TN "<путь>" /DISABLE|/ENABLE`. Цена ошибки: запись неизвестного вида не показана — заказчик заметит «не всё видно», дефект закрывается дополнением источника.
- **RM5b-2 Выключение своей записи — штатно, как Диспетчер задач:** `Run` и папка — значение в `...\Explorer\StartupApproved\Run` / `StartupFolder` (12 байт: первый `0x03` выключено, `0x02` включено, далее FILETIME); задание — `/DISABLE`; магазин — `State=1` (выключено пользователем), включить — `State=2`. Значение в `Run`, ярлык, задание не удаляются. `RunOnce` Windows штатно не выключает — для неё действует только правило наблюдателя (RM5b-3). Профиль ребёнка не загружен — `withHive`.
- **RM5b-3 Правило наблюдателя.** Для ребёнка в сеансе служба держит набор нормализованных путей exe: общие записи с решением `off` у этого ребёнка, свои записи с решением `off`/`pending` (страховка от гонки «Проводник запустил Run раньше, чем служба выключила», и для `RunOnce`). Процесс из набора, запущенный автоматически (`launchKind` → не вручную) в первые `manualLogonGrace` (60 с) после входа, закрывается без плашки и нарушения; в журнал — `evStartupClosed` раз в день на запись. Запущенный ребёнком вручную позже — не трогается (выключена только автозагрузка).
- **RM5b-4 Граница «найдено при первой проверке».** Ключ settings `startup.baseline.<childID>` (UTC мс первой проверки). Первая проверка ребёнка: все записи сохраняются с решением по текущему состоянию Windows (`on` или `off`), ничего не меняется. Последующие: новая запись → `pending`, сразу выключается (RM5b-2) и строка журнала `evStartupNew`. Пропавшая из Windows запись удаляется из таблицы. У общей записи строка на каждого ребёнка; первая проверка общих — по состоянию «включено» (у общих своего выключателя у ребёнка нет).
- **RM5b-5 Когда проверять.** При появлении ребёнка в сеансе (`sessions.go`, `prev != ss.childID`), раз в 10 минут для детей в сеансах (`housekeepStartup`, образец `housekeepBrave`), при старте службы для вошедших, после `SetStartup` и при открытии вкладки (`ListStartup` с `refresh: true` запускает проверку, ответ — текущие строки + `checkedAt`). Проверка асинхронна; одна одновременно на ребёнка.
- **RM5b-6 Значок строки** — значок вида записи (реестр, папка, задание, магазин), не значок exe (ТЗ 8.3.11 уточнено). Извлечение значков exe не делаем.
- **RM5b-7 Скрываемое:** exe под `%WINDIR%` (кроме пользовательских папок), задания под `\Microsoft\`, записи с exe в папке установки PC Block, значения с пустой командой.
- **RM5b-8 Стикеры в окне** — `frontend/src/vendor/lottie_light.min.js` (lottie-web 5.13.0, MIT; файл из тега `v5.13.0` репозитория `airbnb/lottie-web`, `build/player/`) + `frontend/src/vendor/LICENSE-lottie-web.txt`; npm-зависимость не добавляем (в песочнице npm закрыт, lock не обновить). `.tgs` 17 выбранных импортируются Vite как ассеты (`?url`) прямо из `assets/stickers/` (`server.fs.allow` при необходимости); распаковка gzip — `DecompressionStream("gzip")` (WebView2, Chromium); проигрыватель — `renderer: "svg"`, `loop: false`. Остальные 57 стикеров в сборку не попадают (тест сборки: в `dist` ровно 17 `.tgs`).
- **RM5b-9 Стикеры на экране блокировки** — кадры: `tools/sticker-frames.py` (Python, Playwright с установленным Chrome, тот же `lottie_light.min.js`, рендер svg, снимок с прозрачным фоном) → `internal/guard/assets/stickers/<номер>.png`: горизонтальный спрайт кадров 200×200, 15 кадров/с (каждый 4-й кадр 60 fps), палитра 256 цветов с прозрачностью. Файлы генерируются разработчиком и коммитятся (как `rest-cat.png`), генератор не в CI. Проба 14.11: 017 → 41 кадр, 156 КБ.
- **RM5b-10 Надписи выбирают окно и страж, служба отвечает как раньше** («Добавлено N минут», «Код не подходит» — для журнала, плашек и старых клиентов). Неверный код окно и страж распознают по полю ошибки `ipc.FieldCode` (если поля нет у ответа — добавить в `hRedeemPromo`, текст прежний).
- **RM5b-11 B-68 закрыть без пропуска путей:** с M5b стикеры — содержимое программы, изменение `assets/stickers/` должно пересобирать Windows.

## Review Focus (классы, которые задачи не покрывают тестами напрямую)

1. **Гонки входа (класс D, PL-7/PL-8, PL-54):** запись появилась, пока ребёнок не вошёл; вход в момент проверки; перезапуск службы в сеансе ребёнка (`ss.since`); две проверки одного ребёнка одновременно.
2. **Сбой датчика ≠ «записи нет» (PL-46):** ошибка чтения куста/папки/заданий не удаляет строки и не делает записи «новыми» при следующей удачной проверке.
3. **Эффект и отметка — одной транзакцией (PL-55):** «решение в базе» и «штатное выключение в Windows» — порядок: сначала Windows, затем база; при сбое Windows решение не сохраняется, ответ «Не удалось сохранить».
4. **Согласованность представлений (класс A, PL-35, PL-38):** строка в «Ждут решения» после включения переходит в блок и не дублируется; выключатель показывает решение службы, а не нажатие; данные вкладки хранятся с ключом ребёнка (PL-59).
5. **Стикер и надпись (класс B/C):** не повторять прошлый отдельно для удачи и неудачи; надпись с минутами — верная форма слова («+1 минута», «+3 минуты», «+5 минут»); прозрачный фон на тёмной теме; стикер не наезжает на кнопки при 150 % (кольцо фокуса, PL-61, PL-26); удержание экрана 3 с не ломает аварийный выход и пароль родителя (S3, S7, LE1, LE2).
