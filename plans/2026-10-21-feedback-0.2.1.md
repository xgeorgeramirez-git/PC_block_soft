## Review Focus (классы уроков + спека)
1. Согласованность представлений (A): после убирания блокировки за обход статус/карточка/экран/контракт не должны ссылаться на несуществующую блокировку; `CanClearBlock` всегда false.
2. Расчёты и периоды (D): убавление доп. времени — дно суммарного лимита 0; граница суток; отрицательное доп. время + остаток.
3. Приёмка (E): ложное срабатывание обхода при завершении сеанса — детект на штатном конце сеанса.
4. Подсветки/подсказки (B): помощник — покрытие новых элементов (убавление, статистика родителя, галочка логов).
5. Безопасность по умолчанию: убирание блокировки за обход не должно ослабить аварийный выход (экран «время вышло»/«запретные часы» и пароль остаются).

## FB-1 — обход: только журнал, без блокировки (R17, D-41) + ложное срабатывание
**Зона:** internal/core (engine), internal/service (sessions). 
- core: `MarkBypass` пишет только событие `EvBypass` (подробность), НЕ ставит блокировку (`e.bypass` не устанавливается). Ветка `case e.bypass != ""` в `decide` больше не достижима; `ClearBlock`/`e.bypass` остаются как no-op-механика (блокировки за обход нет). 
- service: `procDied`/`superviseWindow` при завершении детского сеанса (WTS disconnect/logoff) помечают процессы `expected` → штатный конец сеанса не пишет обход; принудительное завершение значка/стража/окна — подробная запись в журнал без блокировки; процесс перезапускается (FR-27).
- TDD: core/engine_test (bypass → нет Lock, есть Event); service/sessions_test (конец сеанса не обход; принудительное — журнал, не блокировка); регресс S3/S7/S25/S26.

## FB-2 — галочка «Подробные логи для диагностики» (FR-25, D-42)
**Зона:** internal/storage (настройка verbose_logs), internal/service (уровень лога), frontend Settings.
- storage: ключ настройки `verbose_logs` (bool, default 0) в таблице настроек; миграция при необходимости.
- ipc/service: команда чтения/записи флага; при включённом флаге `Logf` пишет подробный уровень в файл журнала работы.
- frontend: переключатель в Settings с пояснением (8.3.8).
- TDD: storage (get/set флага), service (verbose влияет на объём лога), frontend Settings.test.

## FB-3 — доп. время: своё число + убавить (R10, FR-15, D-43)
**Зона:** internal/core (AddExtra со знаком, дно), internal/ipc (команда), internal/service (handler), frontend Today (кнопки/поле).
- core: `AddExtra(min)` принимает отрицательное; суммарный лимит (лимит дня + доп.время) не ниже 0 → доп.время ограничено снизу `-(лимит дня)`; «Убрать доп. время» = установить доп.время дня в 0. Эталон поведения — юнит-таблица.
- ipc: расширить `AddExtra` знаком или добавить команду; TS-зеркало.
- service: handler принимает отрицательное от родительской сессии (не от ребёнка).
- frontend Today: кнопки −15/−30/−60, «Своё время…» (поле ±минут), «Убрать доп. время»; подтверждения/сообщения («Убрано 30 минут», «Отменить» 10 с).
- TDD: core (убавление, дно, обнуление), ipc contract, Today.test (кнопки, поле, вызовы).

## FB-4 — базовая статистика родителя за сегодня (FR-23, D-44)
**Зона:** internal/ipc (данные статистики по ребёнку из родительской сессии), internal/service (handler), frontend (экран/переиспользовать MyStats + выбор ребёнка, пункт меню, кнопка «Статистика» на карточке).
- ipc/service: команда «статистика ребёнка за сегодня» для родительской сессии (итоги, категории, нарушения, копилка, правила) — переиспользовать существующий источник «Моей статистики».
- frontend: экран ParentStats (или MyStats с выбором ребёнка и заголовком), доступен из меню «Статистика» и кнопкой «Статистика» на карточке Today; только просмотр.
- TDD: service (данные выбранного ребёнка, только родитель), frontend (экран, выбор ребёнка, нет полей ввода).
