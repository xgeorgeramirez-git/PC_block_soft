# Промты для чатов вех

Одна веха — один новый чат. Вехи запускаются по порядку; следующую — только после закрытия предыдущей (её выпуск в Releases). Скопируйте блок нужной вехи целиком в новый чат.

Общее для всех вех (входит в каждый промт ниже): работа по `CLAUDE.md`; ТЗ правится заменой текста; блокировки испытываются только в CI; тяжёлые прогоны строго по лестнице R0–R4; конвейер «два слота» (не больше двух субагентов, один писатель) с реестром `plans/M<N>-agents.md`; визуальная проверка — агент `visual-reviewer`.

```text
Прочитай: CLAUDE.md; docs/00_START_ЗДЕСЬ.md; ТЗ docs/01_ТЗ.md — разделы 1–5, 7, 8.0–8.2.3, 8.3.1–8.3.3, 8.3.8, 9 (строка M1), 10, 11 (S1…S7, S25…S27); эталоны docs/04_Эталоны_учёта.md (G1, G2, G3, G9, G10); docs/LESSONS.md; plans/BACKLOG.md (B-1); references/lessons.md и references/gotchas.md скилла (Windows, Wails, Go/SQLite, NSIS).
Состав вехи — ТЗ, раздел 9, строка M1.
Skills to load: dev-methodology, git-guru, uiux-design, usability-heuristics; web-design-guidelines — на ревью диффа интерфейса; in-app-guidance — только если на гейт-вопрос я отвечу «да».

Порядок:
1. Фаза 1 — разведка. Задай мне один раз гейт-вопрос: внедряем ли систему подсказок и обучения (in-app-guidance). Решение запиши в ТЗ и план.
2. Фаза 2 — план plans/<дата>-M1.md по шаблону методики: UX-сценарий, Review Focus, Global Constraints дословно из ТЗ, Skills to load. Первая задача — проба неубиваемого экрана блокировки (ТЗ 3.2: страж от имени системы в сеансе ребёнка); итог пробы — Ruling в плане. Ревью плана свежим субагентом.
3. Фазы 3–7 — конвейер «два слота», реестр plans/M1-agents.md, TDD. Ядро правил и учёта — только стандартная библиотека, тесты локально; эталоны → testdata/golden/*.json. Всё с Wails, SQLite и Windows — через CI. Лестница R0–R4 строго: full-series.yml (R4) — ровно на закрытии вехи и после ревью-фиксов.
4. Приёмка — S-сценарии вехи в CI на windows-latest в тестовом режиме; снимки экранов в ветку screenshots; визуальная проверка — агент visual-reviewer; UX-аудит снимков по usability-heuristics. Блокировки на моём компьютере не запускать.
5. Фаза 8 — версия 0.1.0 (internal/version/version.go, wails.json, CHANGELOG.md), README, CLAUDE.md, docs/LESSONS.md, docs/CODEMAP.md, plans/BACKLOG.md, запись в docs/HISTORY.md. Код — ветка feature/m1-time-limit → Pull Request → зелёный CI → слей в main сам (выпуск появится в Releases).

Работай сам; спрашивай только гейт-вопрос, при неясном объёме или перед разрушительным действием. Изменения требований — сначала в ТЗ заменой текста.
Готово значит: S1…S7, S25…S27 и G1, G2, G3, G9, G10 зелёные в CI; серия R4 зелёная; выпуск 0.1.0 в Releases; короткий отчёт мне: что умеет версия, как поставить на запасной ПК, что проверить руками.
```
