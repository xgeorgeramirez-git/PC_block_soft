# План вехи M3 «Программы и игры» (версия 0.3.0)

**Goal:** убрать Помощник (D-56) и научить программу считать и ограничивать игры, не считать учёбу, не пускать незнакомые программы без решения родителя и оставлять в конце времени только учёбу.

**Architecture:** ядро (`internal/core`, только стандартная библиотека) получает лимит игр, режим окончания и решение «что закрыть» (`Decision.CloseGames`, `Decision.StudyOnly`, `Decision.Allows(cat)`); служба классифицирует программы по пути exe (таблица `programs`), следит за процессами ребёнка через новый порт `ProcessWatcher` и закрывает запрещённое не позже 1 с; страж присылает путь программы на переднем плане и показывает плашки; экран «Программы» в окне родителя решает судьбу «ждущих решения».

**Tech Stack:** Go 1.27 (служба SYSTEM, Win32 через `golang.org/x/sys/windows`), SQLite (modernc), Wails v2 + React/TS/Vite, PowerShell-приёмка на windows-latest.

**Спека:** `docs/01_ТЗ.md` 1.8 — R3, R4, R5, R8, R9, R12, R13, R23, FR-2, FR-13, FR-16, FR-18, FR-20, FR-36, разделы 8.2.4, 8.3.4, 8.3.9, S12…S15, S36, S37; `docs/04_Эталоны_учёта.md` G4, G5, G12 (файлы `testdata/golden/G4.json`, `G5.json`, `G12.json` уже в ветке, КРАСНЫЕ до задачи 2); решения D-3, D-9, D-14, D-54, D-56.

**Ветка:** `feature/m3-programs` (от main с ТЗ 1.8). Дерево `/home/claude/pc_block_soft`. Один писатель за раз (правило «два слота»); оркестратор в дерево не коммитит, пока писатель работает.

## Global Constraints (дословные ограничения проекта)

- Ядро `internal/core` — только стандартная библиотека. Правила, цифры и тексты считает ядро; служба, страж, значок, окна — только показывают (Review Focus 5 методики).
- Тексты ребёнку на «ты», родителю на «вы», без длинных тире (`python3 tools/scan_ui_texts.py`), без технических ошибок.
- Репозиторий публичный; self-hosted runner заказчика к workflow НЕ привязывать; на ПК заказчика ничего не ставить и блокировки не запускать; приёмка только на машинах GitHub в тестовом режиме.
- Аварийный выход (NFR-10) в каждой версии: S3, S7, S25, S26 в регрессе. Экран блокировки всегда содержит ввод пароля родителя (R18). Новый код не может заблокировать компьютер без выхода: ошибка классификатора или наблюдателя процессов = «не закрывать», событие в журнал.
- Наблюдатель не завершает никогда: класс «система» по префиксам пути (точные префиксы с разделителем из KnownFolders: `%SystemRoot%`, каталог установки PC Block из `os.Executable` — служба, страж, значок, окна, `WindowsApps`, `Program Files*\Microsoft\EdgeWebView`), процессы вне сеанса ребёнка, процессы родительских сеансов (R19), процессы с нечитаемым путём или неизвестным сеансом (PL-9: «не знаю» = «не трогать»), защищённые процессы (отказ `OpenProcess` — запись в журнал работы, не в журнал родителя). Гибель окон PC Block от наблюдателя недопустима (иначе запись «обход защиты», PL-13).
- Предупреждения об играх: пороги 30/15/5/1 (D-54), табло за 30/15/5, плашка 1 мин, звук заказчика — тот же путь, что для общего лимита (0.2.5). Порог взводится только если до события строго больше его минут (PL-14). Один порог — одно уведомление.
- Завершение процесса не позже 1 с (NFR-6) для программ, вкладки — M4. Завершение вне блокировки `s.mu`.
- Версия 0.3.0 меняется в `internal/version/version.go` и `wails.json` вместе (тест сверяет).
- ТЗ править только заменой (D-35); изменение требования = сначала ТЗ + D-N + HISTORY.
- `go.sum` обновляет CI; GraphQL закрыт — PR и слияние через `gh api` (CLAUDE.md).
- Известные нестабильные: `TestRunStartsOneGuardAndStopsOnClose` (B-20) — перезапускать только упавшее.

## Решения оркестратора (Ruling, действуют, пока заказчик не изменит)

- **RM3-1. Что считается «игрой» и «незнакомой».** Категория программы определяется по таблице `programs` (ключ — полный путь exe в нижнем регистре после `GetLongPathName`, без 8.3-имён; junction разворачивается). Порядок: (1) класс «система» (см. Global Constraints) → не трогать, секунда как «Прочее»; (2) точное совпадение пути в `programs` → её категория (для решений родителя вне доверенных каталогов сверяется отпечаток файла: размер и время изменения; расхождение = программа снова «ждёт решения», в строке «раньше: Игра», RM3-12); (3) путь внутри **корня приложения** известной программы (`<доверенный корень>\<первая папка>`, например `C:\Program Files\Brave Software`) → категория этой программы (вспомогательные exe и обновления версий наследуют; «Игры» от вспомогательных exe тоже); (4) каталог игр и браузеров по имени файла — только для путей в доверенных каталогах; (5) иначе, если путь вне `%SystemRoot%` → «незнакомая» (R12). Доверенные каталоги — точные префиксы `%ProgramFiles%\`, `%ProgramFiles(x86)%\`, `%SystemRoot%\` (`C:\Program Files Games\` в них НЕ входит).
- **RM3-2. Brave.** В M3 Brave — «Прочее» (всё сайты M4). В режиме «Оставить только учёбу» Brave закрывается целиком (вкладки по доменам — M4); запись в README «Отклонения от ТЗ».
- **RM3-3. Издатель и значок.** Издатель = `CompanyName` из свойств файла, иначе «Без подписи издателя»; значок общий; подпись Authenticode не проверяется (README «Отклонения», бэклог).
- **RM3-4. «Попросить сейчас».** Кнопка на плашке «ждёт разрешения» открывает окно родителя на экране «Программы → Ждут решения» (маршрут `--screen=programs`); пароль родителя и решение — в этом окне (тот же путь, что «Настройки для родителя» из окна ребёнка). Для заказчика результат тот же, что в 8.2.4: пароль, затем сразу выбор «Игра», «Учёба», «Прочее», «Запретить»; отличается только окно (окно родителя вместо маленького диалога на плашке). После решения «Игра/Учёба/Прочее» программу запускает ребёнок сам, плашка: «Родитель разрешил «X»: это игра. Запусти её снова». Отклонение записать в README «Отклонения от ТЗ» и в отчёт заказчику; ТЗ не меняется.
- **RM3-5. Кнопки плашки 1 мин (B-27).** «Взять из копилки» (без пароля, `CmdSpendBonus`, правило `childSelf`/страж; нет кнопки, если копилка пуста или идёт запретный интервал, 8.2.2 п.4, FR-11) и «Попросить ещё» (открывает «Моя статистика», как значок).
- **RM3-6. Учёт по программам.** `usage_daily` пишется службой раз в тик по категории и программе (subject_kind = `program`, subject = путь exe в нижнем регистре), сохранение вместе с `day_state`.
- **RM3-7. Секунда запрещённой категории не считается.** `Accumulator.Tick` не засчитывает секунду, если `!Decision.Allows(foreground)` (игра после исчерпания лимита игр; всё, кроме учёбы, в режиме «только учёба»): иначе G5/G12 разъезжаются на секунды закрытия.
- **RM3-8. Тестовый режим приёмки.** Тестовые программы — копии `notepad.exe` во временной папке (вне доверенных каталогов): незнакомые по определению; решение родителя даётся командой канала через `--test-ipc`. В тестовом режиме наблюдатель трогает только процессы, чей путь внутри папки `WatchDir` (значение реестра `HKLM\SOFTWARE\PCBlock\TestMode\WatchDir`, поле в `TestModeValueNames` и `ParseTestMode`); иначе он завершил бы раннер. Передний план в сценариях ставится приёмом `PcbNative.ForceForeground` (как в S2/S35); сценарии S12…S15 сначала настраивают ребёнка, потом дают решения по программам (PL-11). Дополнительно «сухой прогон» на windows-latest: перечислить процессы сеанса раннера и вывести пометкой, что наблюдатель СЧИТАЕТ закрываемым вне `WatchDir` (ожидание: ничего).
- **RM3-10. Обновление 0.2.5 → 0.3.0 и первый старт.** У настроенной установки таблица `programs` пуста. Служба при первом старте после миграции делает снимок (корни приложений `Program Files*` и каталог) и ставит флаг `programs.seeded` в `settings`; **пока флага нет, наблюдатель ничего не закрывает** (R18). Тест: база версии 0.2.5 без `programs` → ничего не закрыто, после снимка Brave и вспомогательные процессы не «незнакомые».
- **RM3-11. Где живёт наблюдение.** Опрос процессов — собственный тикер службы по настоящим часам, ~250 мс (не зависит от `ClockSpeed` и от `TickInterval`); классификация только из памяти (карта `programs` и корни приложений перезагружаются при изменении решений), без SQLite в тике; путь кэшируется по `(pid, время создания)`; завершение — через ручку, открытую при чтении пути, вне `s.mu`.
- **RM3-12. Подмена файла.** Для решения родителя по программе вне доверенных каталогов запоминается отпечаток (размер, время изменения); расхождение = программа снова «ждёт решения» с пометкой «раньше: <категория>». Для каталога и снимка в доверенных каталогах отпечаток не нужен (ребёнок туда писать не может).
- **RM3-13. Программы в профиле пользователя (по сухому прогону windows-latest 40954826900).** Снимок раннера показал «незнакомыми» процессы вне Program Files: помощник Защитника Windows (`C:\ProgramData\Microsoft\Windows Defender\Platform\<версия>\`), а у заказчика так же будут OneDrive, Teams, Discord, Roblox, лаунчеры игр в `%LOCALAPPDATA%`/`%APPDATA%`. По R12 они ждут решения родителя (это верно), но (а) защитник и компоненты Windows закрывать нельзя, (б) решение родителя не должно теряться при каждом обновлении программы (новая папка версии `app-1.0.123`, `version-abc`, новый отпечаток). Правило: класс «система» дополняется точными префиксами `%ProgramData%\Microsoft\Windows Defender\` и `%ProgramData%\Microsoft\Windows Defender Advanced Threat Protection\`; для решений родителя в профиле пользователя (`%LOCALAPPDATA%\`, `%APPDATA%\`, `%LOCALAPPDATA%\Programs\`) корень приложения — первая папка под этим корнем (для `Programs` — вторая), и решение распространяется на exe **с тем же именем файла и тем же издателем** (`CompanyName`) внутри того же корня (обновления версий); другой exe в той же папке — снова «ждёт решения»; отпечаток проверяется только для точного пути. В «Загрузках», на рабочем столе и в прочих папках — только точный путь с отпечатком (RM3-12).
- **RM3-9. Исправление найденной ошибки.** `hSaveLimits` пересобирал правила без расписания (запретные часы пропадали в памяти службы до перезапуска): в задаче 3 заменить на `s.readRules(id)`, регресс-тест первым.

## UX-сценарий (родитель и ребёнок)

Ребёнок: скачал `SuperGame.exe` в «Загрузки», запустил → не позже 1 с окно закрыто → в правом нижнем углу плашка «Программа «SuperGame» ждёт разрешения родителя», кнопка «Попросить сейчас». Нажал → открылось окно родителя с запросом пароля (родитель рядом) → после пароля экран «Программы», вверху «Ждут решения: 1»: SuperGame, издатель, путь, «Миша, 3 попытки, вчера 18:40», кнопки «Игра» «Учёба» «Прочее» «Запретить». Нажал «Игра» → сообщение «SuperGame: игра» с «Отменить» 10 с → ребёнку плашка «Родитель разрешил «SuperGame»: это игра. Запусти её снова» → запустил, пошёл счёт игр. Лимит игр 60 мин: за 30/15/5 табло и звук («Сохрани игру: через 5 минут время на игры закончится»), за 1 плашка с кнопками «Взять из копилки», «Попросить ещё»; в 0 игра закрыта, плашка «Время на игры на сегодня закончилось», остальное работает. Режим «Оставить только учёбу»: время вышло → плашка «Время вышло. Сейчас доступна только учёба», всё кроме учёбы и системного закрыто, экрана блокировки нет; попытка запустить игру → закрыта ≤ 1 с, в журнале «Закрыто: время вышло, доступна только учёба».
Ошибки: путь не читается → программа не закрывается, событие в журнал; родитель не успел → программа остаётся в «Ждут решения», счётчик попыток растёт; «Запретить» → при запуске плашка «Программа «X» запрещена родителем», журнал «попытка открыть запрещённое» (не блокирует экран, D-33).
Родитель, экраны: «Программы» (FR-20); «Дети → ребёнок → Лимиты» с колонкой «Игры» (FR-16); вкладка «Когда время вышло» (FR-18) с предупреждением «Учебных программ и сайтов пока нет: в этом режиме будет закрыто всё» и ссылкой на «Программы»; шаг мастера «Программы» (FR-2); внизу меню «Что нового» (FR-36).

## Review Focus (классы входов и отказов, не покрытые задачами напрямую)

1. **Дубли уведомлений (PL-13, PL-14, класс A):** порог игр взводится строго «больше»; пересчёт без сдвига события не повторяет; «+30» при исчерпанных играх; доп. время расширяет лимит игр так же, как общий; два порога (игры и общий) в один тик — одно уведомление (меньший остаток), равные — общий.
2. **Штатные завершения vs нарушения (PL-5, PL-13):** закрытие процессов наблюдателем при выходе/смене пользователя/выключении не пишется «обходом»; гибель стража/значка, вызванная завершением процессов наблюдателем, не должна происходить (исключения из списка убиваемых).
3. **Самоубийство раннера и системы (класс E):** путь exe, 8.3-имена (`RUNNER~1`), нечитаемый путь (`Access denied`), процессы без сеанса; наблюдатель не убивает то, чей путь не прочитан.
4. **Сутки и снимки (PL-15):** категория переднего плана и решение — из одного кадра; смена суток обнуляет остаток игр; частичные пути сохранения правил не теряют соседние поля (`Rules` целиком: лимиты, игры, режим окончания, расписание) — регресс RM3-9.
5. **Общее правило «учёба не считается» (класс D):** Study не входит в TotalS ни при Allows=false, ни при паузе, ни при смене суток; игры идут в TotalS и GamesS одновременно.
6. **Классификация (классы A/D):** одна программа — одна категория для всех детей; смена категории родителем действует на уже запущенные процессы на следующем тике; «Запретить» запущенной сейчас программы закрывает её.
7. **Поверхность атаки (реальная):** переименование exe в «Загрузках» (RM3-1, каталог только в доверенных каталогах), подмена файла с тем же путём (RM3-12), `C:\Program Files Games\`, 8.3-имена и junction (нормализация), вспомогательные процессы (WebView2, Brave) — наследуют категорию корня приложения; путь стража служба сверяет со списком процессов сеанса, который видит сама.
8. **Самоповреждение (PL-13, PL-9):** наблюдатель не убивает компоненты PC Block, WebView2, WindowsApps; гибель окон от него не пишется «обходом»; неизвестный сеанс/нечитаемый путь = «не трогать»; обновление 0.2.5 → 0.3.0 до снимка программ ничего не закрывает (RM3-10).
9. **Приёмка (PL-16, PL-11, PL-7/8):** ждать текст плашки и счётчик журнала, а не окно; фейки и тестовые состояния убирать в `t.Cleanup`; случай «передний план не определён/нечитаем»; сценарии сначала настраивают ребёнка, потом решения по программам.
10. **Все экраны, где есть остаток:** игры доходят до значка (подсказка «Игры: 20 мин»), карточки «Сегодня» («Игры 40 мин из 1 ч»), «Моей статистики», «Моих правил» (R21), ссылки «Ждут решения: N» (8.3.2 п.5); FR-33 «копирование правил» копирует и игры, и режим окончания; кнопка «Взять из копилки» скрыта в запретный интервал.

## Лестница прогонов

- После каждой задачи писатель: `go test -race` затронутых пакетов, `go vet`, `gofmt`, фронт `vitest`+`tsc`+`vite build` (R1/R2 локально), `GOOS=windows go vet` через временный modfile для кода Windows.
- После T1, T2, T3, T4, T5, T6: push ветки → `ci.yml` (R2, ubuntu).
- После T4–T7: `windows.yml` (R3) — сборка, тесты Windows, приёмка `only=S12,S13,S14,S15` и регресс `S2,S35` (предупреждения), `S3,S7,S25,S26` (аварийный выход).
- Закрытие вехи: ревью диффа свежим агентом → фикс-раунд → `full-series.yml` (R4, один раз) → PR → `ci.yml`+`windows.yml` зелёные → слияние в main → выпуск 0.3.0.
