# План вехи M4 «Сайты и Brave» (версия 0.4.0)

> Оркестратор вехи исполняет план конвейером «два слота» (dev-methodology, раздел «Конвейер вехи»): один писатель за раз, читатель готовит пакет следующей задачи; реестр — `plans/M4-agents.md`; пакеты — `plans/packets/M4-T<N>-*.md`.

**Goal:** программа различает сайты в Brave: закрывает запрещённые и «18+» вкладки, считает и ограничивает время на видео и соцсети, учёбу на сайтах не считает, закрывает другие браузеры, отключает в Brave окна Tor, VPN, защищённый DNS и установку расширений; приложение из магазина Microsoft — одна строка на все версии.

**Architecture:** страж (SYSTEM, сеанс ребёнка) читает адрес активной вкладки Brave через UI Automation, берёт из него только домен и шлёт его в снимке датчиков; служба по домену решает категорию и вердикт (пакет `internal/sites`: нормализация, свои списки, встроенный список «18+»), учитывает секунды по сайтам, просит стража закрыть вкладку и показывает плашку; ядро получает лимит «Видео и соцсети» по образцу лимита игр; служба пишет правила Brave в ветку реестра ребёнка и сверяет их раз в 60 с; классификатор программ запрещает прочие браузеры и даёт приложениям магазина ключ без версии пакета; окно родителя получает экран «Сайты», колонку «Видео» в лимитах и шаг мастера «Сайты».

**Tech Stack:** Go 1.27 (служба и страж от SYSTEM, Win32 и COM UI Automation через `golang.org/x/sys/windows`), SQLite (modernc), Wails v2 + React/TS/Vite, PowerShell-приёмка на windows-latest с установленным Brave.

**Спека:** `docs/01_ТЗ.md` 1.18 — A3, R2, R3, R6, R8, R10, R13, R14, R15, R23, FR-2, FR-9, FR-12, FR-13, FR-16, FR-20, FR-21, FR-23, FR-31, NFR-1, NFR-4, NFR-5, NFR-6, разделы 3.2, 3.4, 8.2.4, 8.2.5, 8.3.3, 8.3.4, 8.3.5, 9 (M4), 10, 11 (S16…S20, S46, ST2); решения D-8, D-19, D-22, D-33, D-63…D-68.

**Ветка:** `feature/m4-sites` (от main с ТЗ 1.18). Дерево `/home/claude/pc_block_soft`.

## Решения оркестратора (Ruling, действуют, пока заказчик не изменит)

- **RM4-0. Среда.** npm из песочницы недоступен (прокси отказывает `registry.npmjs.org`), фронт проверяет только `ci.yml`; писатель фронта прогоняет `ci.yml` через оркестратора (push) вместо локального R1. Цена: петля фронта медленнее; компенсация — фронт-задачи крупнее и с полным набором тестов до push.
- **RM4-1. Чтение домена (проба T0, итог фиксируется Ruling-ом в этом файле).** Страж, если на переднем плане `brave.exe`, ищет в окне переднего плана поле адреса Chromium (UIA: элемент `Edit` с `ClassName = "OmniboxViewViews"`, без опоры на локализованное имя) и читает `ValuePattern.Value`; из текста берётся только домен (`sites.FromOmnibox`). Если поле адреса в фокусе клавиатуры (ребёнок печатает), домен не меняется (берётся прошлый для этого окна). Не нашлось поле или UIA вернул ошибку — домен «», запись в журнал работы раз в 10 мин и в журнал родителя раз в день «Не удалось прочитать адрес сайта в Brave» (RK5). Элемент поля адреса кэшируется для каждого окна (hwnd), поиск — только в рамке окна, без захода в дерево страницы (NFR-5: проба меряет процессор стража и Brave). Окно Brave без поля адреса (сайт-приложение `--app-id`/`--app=`, всплывающее окно): домен берётся из `ValuePattern` корневого элемента `Document` (адрес документа), если проба это подтвердит; не вышло — окно без домена: в режиме «только учёба» и при исчерпанном лимите видео такое окно закрывается (`WM_CLOSE`), иначе секунды — «Прочее». Служебные страницы (`brave://…`, новая вкладка) — домен «», «Прочее»; в режиме «только учёба» они не закрываются, чтобы Brave оставался пригоден. Запасной путь, если от SYSTEM в сеансе ребёнка UIA не работает: чтение в значке (от имени ребёнка) — решение принимает оркестратор по итогу пробы.
- **RM4-1-итог (проба T0, прогон windows.yml 42036478891, Brave 156.1.98.63 от choco в профиле раннера).** От имени пользователя раннера: поле адреса — `Edit` (50004) с `ClassName = "BraveOmniboxViewViews"` (поиск — по окончанию `OmniboxViewViews`), домен прочитан за 3,5 с после открытия окна (холодное дерево доступности), дальше — каждое чтение ≤ 6 мс, 60 чтений — 31 мс процессора стража; окно сайта-приложения (`--app=`) тоже имеет поле адреса. Чтение от SYSTEM в сеансе ребёнка работает (сценарий PROBE, прогон 42037977336: страж прочитал домен за 0,6 с) — запасной путь через значок не нужен.
- **RM4-2-итог.** Ctrl+W через `SendInput` и UIA-кнопка закрытия вкладки закрывают вкладку сразу (≤ 0,1 с); закреплённая вкладка пробой не проверена (закрепить можно только меню) — лестница RM4-2 остаётся.
- **RM4-2. Закрытие вкладки.** Служба в ответе на опрос стража даёт команду `closeTab{Domain}`; страж непосредственно перед действием перечитывает передний план и домен, и только если это то же окно Brave с тем же доменом, посылает Ctrl+W (`SendInput`); если зажаты Shift, Alt или Win (`GetAsyncKeyState`), действие откладывается до следующего опроса (Ctrl+Shift+W закрыл бы всё окно). Иначе команда отбрасывается, следующий опрос даст новую. Лестница при неудаче (домен тот же через 2 с после команды): вторая попытка — UIA `Invoke` кнопки закрытия выбранной вкладки (закреплённая вкладка по Ctrl+W не закрывается), третья — `WM_CLOSE` окну Brave с той же плашкой. Проба T0 проверяет обычную и закреплённую вкладку.
- **RM4-3. Список «18+» (D-67).** Источник — `blacklists/adult/domains*` зеркала `github.com/olbat/ut1-blacklists` на закреплённом коммите (`tools/adultlist/ut1.commit`). Инструмент `tools/adultlist` (стандартная библиотека) строит файл `internal/sites/adult/adult.bin`: 44-битные хеши FNV-1a нормализованных доменов, корзины по старшим 20 битам (смещения `uint32`) + младшие 24 бита (3 байта) ≈ 18 МБ. Файл встраивается `go:embed` в переменную типа `string` (раздел только для чтения, общие страницы образа, а не личная память процесса) и читается на месте, без копирования в кучу. Голые зоны верхнего уровня, которые UT1 закрывает целиком (сейчас `xxx`, `porn`, `sex`, `adult`), хранятся в файле отдельным набором зон: домен с такой последней меткой — «18+» (RM4-3а). В репозитории лежит пустой файл того же формата (0 доменов, 0 зон); полный строится в `windows.yml` перед `wails build`; тест `TestAdultListFull` (при `PCB_ADULT_FULL=1`) требует ≥ 4 000 000 доменов, и шаг выпуска без него не идёт. Проверяются домен и его родительские домены, кроме голого домена верхнего уровня (`com`); ложное совпадение хеша — около 1 на миллион проверок домена; результат кэшируется (не больше 4096 доменов); цена — сайт закрыт как «18+», родитель снимает добавлением домена в «Учёбу» или «Видео» (RM4-5); запись в README «Отклонения от ТЗ». Лицензия: файл `internal/sites/adult/LICENSE-UT1.txt` (CC BY-SA 4.0, источник) идёт рядом с программой, подпись на экране «Сайты» (ТЗ 8.3.5 п. 3).
- **RM4-4. Домен.** Хранится и сравнивается нижним регистром, без `www.` в начале, без точки в конце, IDN — в punycode (свой кодировщик RFC 3492 в `internal/sites`). Совпадение — сам домен и все поддомены (R14). Ввод родителя (FR-21): домен или вставленный адрес; не домен (нет точки, пробел, запрещённые символы, длина > 253) — ошибка «Это не похоже на адрес сайта». IP-адрес — допустим как домен.
- **RM4-5. Один домен — один список; порядок решения.** Миграция 009 оставляет у домена одну запись (`UNIQUE(domain)`; повтор при добавлении в другой список переносит домен, ответ «Сайт перенесён в …»). Для домена вкладки берётся самая длинная совпавшая запись своих списков: «Запрещённые» → закрыть; «Учёба» → «Учёба»; «Видео и соцсети» → «Видео и соцсети». Ни одна не совпала: включён «18+» у ребёнка и домен в списке → закрыть «для взрослых»; иначе «Прочее». То есть свои списки родителя сильнее «18+» — это отклонение от буквы R13 (README «Отклонения от ТЗ»), сообщается заказчику в отчёте вехи.
- **RM4-6. Лимит «Видео и соцсети» (R6).** Ядро: `DayLimit.VideoMin *int` (nil — без лимита, 0 — нельзя), `RemainingVideoS` по образцу игр, доп. время расширяет и его (R10), `Decision.CloseVideo` + `VideoRemainingS/VideoLimitS/VideoUnlimited`, `WarnVideo` с порогами при `fg == CatVideoSocial`; секунда видео при `!Allows(CatVideoSocial)` не засчитывается (как RM3-7). В режиме «Оставить только учёбу» (R8) Brave разрешён только на доменах «Учёбы», остальные вкладки закрываются (снимает RM3-2).
- **RM4-7. Учёт по сайтам.** Секунда с Brave на переднем плане и известным доменом пишется в `usage_daily` с `subject_kind = 'site'` и `subject` = совпавшая запись списка (иначе домен вкладки); с доменом «» — как программа Brave. Видео идёт в учёт (сейчас `usageCats` его пропускает). «Итоги» (вкладка «Видео и соцсети» и др.) показывают строки сайтов; «Пока не считается» убирается.
- **RM4-8. Браузеры (R15, D-68).** Каталог: `brave.exe` — «Прочее» (сайты решают); остальные браузеры каталога — «Запрещено» по имени файла в любом каталоге (переименованный браузер вне доверенных — «незнакомая», то есть тоже закрыт). Brave разрешён из доверенных каталогов и из своей папки в профиле (`%LOCALAPPDATA%\BraveSoftware\Brave-Browser\Application\brave.exe`, правило профиля PL-20: имя файла + издатель «Brave Software»); `brave.exe` в другом месте — «незнакомая». `msedgewebview2.exe` и `msedge_proxy.exe` браузерами не считаются (WebView2 — системный, PL-18). Миграция 009 переводит браузеры, у которых категорию ставил не родитель (`source` в `catalog`, `snapshot`), в «Запрещено»; решение родителя в «Программах» остаётся сильнее. Плашка браузера — «Этот браузер запрещён. Пользуйся Brave» (8.2.5 п. 4) вместо «Программа «X» запрещена родителем»; автозапуск браузера — молча (R13, D-65, `launchKind`).
- **RM4-9. Старшинство плашек.** Плашки сайтов (`siteBlocked`, `siteAdult`, `videoOver`, `browserForbidden`) — того же уровня, что плашки о программах (`BlockedPlate`); порядок PL-34 не меняется: конец времени, запретные часы, пауза, «Добавлено» выше; отдых ниже. Повтор той же плашки о том же домене — не чаще раза в 5 с (`plateEvery`), нарушение «попытка открыть запрещённое» о домене — не чаще раза в 60 с (`watchRepeatEvery`).
- **RM4-10. Правила Brave (R15, FR-31).** Порт `Policy` получает `SetBraveRules(sid string, r BraveRules) error` и `BraveRulesOK(sid string, r BraveRules) (bool, error)`; ветка `HKU\<SID>\Software\Policies\BraveSoftware\Brave` целиком принадлежит программе: `TorDisabled=1`, `BraveVPNDisabled=1`, `DnsOverHttpsMode="off"`, `ExtensionInstallBlocklist\1="*"`, `URLBlocklist\1..N` = домены «Запрещённых» (≤ 1000). Запись при старте службы, при изменении списков и при сверке раз в 60 с; расхождение восстанавливается и пишется в журнал родителя «Правила Brave восстановлены»; при удалении программы и снятии отметки «детская» ветка удаляется. Загрузка ветки без входа ребёнка — тот же путь, что `DisableTaskMgr` (`viaProfile`). Применяет ли Brave пользовательские политики из HKCU на компьютере без домена — проверяет проба T0 (ключи в HKCU раннера → `brave://policy` показывает их действующими, кнопки VPN нет, пункта окна Tor нет, запрещённый домен — страница блокировки); итог дописывается сюда до T5. Если HKCU не применяется — вопрос заказчику (HKLM затронет и родителя).
- **RM4-11. Приложения магазина (D-66, FR-20, S46).** Ключ программы из `<PF>\WindowsApps\<имя>_<версия>_<арх>_<ресурс>_<издатель>\<путь exe>` — `<PF>\windowsapps\<имя>__<издатель>\<путь exe>` (`programs.StableKey`); то же для поиска, классификации, учёта и «Ждут решения». Издатель — `PublisherDisplayName` из `AppxManifest.xml` пакета (любой существующей версии), для `8wekyb3d8bbwe` без манифеста — «Microsoft Corporation». Корень `WindowsApps` защищён TrustedInstaller, поэтому в тестовом режиме он подменяется значением `TestMode\StoreRoot` (подпапка `WatchDir` с поддельными папками версий и `AppxManifest.xml`); повторы «до обновления» засеваются тестовой командой `TestSeedPrograms` (только в тестовом режиме, тест обработчика — PL-41). Слияние накопившихся повторов — однократно в Go при старте службы (флаг `programs.storemerged` в `settings`) одной транзакцией: категория — последнее решение родителя (по `decided_at`), из двух флагов строгий (запрет сильнее скрытия, PL-30), скрытие сохраняется, своё название — последнее непустое, учёт `usage_daily` суммируется на ключ, попытки «Ждут решения» суммируются.
- **RM4-12. Тестовый режим.** Тестовые действия стража: `domain` (подмена домена вкладки, пустой текст снимает) по образцу `foreground` (PL-41: тест `hTestGuard` с этим действием); `GuardStateReply.ForegroundDomain` и последняя исполненная `closeTab`. Приёмка S16…S18 открывает настоящий Brave на доменах, которые в `hosts` раннера указывают на 127.0.0.1 (на раннере ничего не грузится из сети); S16 берёт настоящий домен из встроенного списка UT1. Brave на раннере ставится офлайн-установщиком закреплённой версии (`choco install brave --version <закреплённая> -y`; проба выясняет, что работает), запуск с `--no-first-run --no-default-browser-check`. S20 проверяется так: значения в ветке реестра ребёнка, UIA-поиск в окне Brave кнопки VPN и пункта меню «Новое окно Tor» (их нет), снимок страницы `brave://policy` (разбирает `visual-reviewer`). S18 — с ускоренными часами (`Initialize-Scenario`), текст предупреждения о видео по 8.2.2.

## Review Focus (классы входов и отказов, не покрытые задачами напрямую)

1. **Домен из адресной строки и окна без неё (класс D, RM4-1, RM4-4):** окно сайта-приложения, всплывающее окно, «Картинка в картинке»; `brave://newtab`, поисковая фраза, `view-source:`, `file:///`, `localhost:3000`, IP с портом, IDN, `WWW.Example.COM.`, логин в адресе `user@host`, пустая строка, 2000 символов; печатание в поле адреса. Фаззинг `FromOmnibox` и `NormalizeInput`.
2. **Самоповреждение и систему не трогать (PL-18, PL-19, PL-9):** WebView2 и окна PC Block не браузеры; Ctrl+W не уходит в чужое окно (передний план сменился между решением и действием); нечитаемый передний план — ничего не закрывать; родительская учётка и неотмеченные учётки — без правил Brave.
3. **Строгий флаг и смена сущности (PL-30, PL-38, PL-40):** слияние повторов магазина — запрет сильнее скрытия; решение родителя сильнее каталога браузеров; «Итоги» по сайтам — показ по текущему списку (сайт перенесён из «Видео» в «Учёбу» — строка в «Учёбе» только с этого момента, прошлые секунды остаются в своей категории); дочерние процессы браузера — одно нарушение (PL-40).
4. **Дубли и старшинство уведомлений (PL-13, PL-14, PL-34):** порог видео взводится строго «больше»; одновременно игры и видео не на переднем плане — видео-порог только при видео на переднем плане; плашки сайтов не вытесняют плашку 1 мин с кнопками; повтор плашки и нарушения — по RM4-9; доп. время, копилка, промокод расширяют видео.
5. **Снимок из одного момента (PL-15):** путь переднего плана и домен — из одного прохода `readRaw`; решение о закрытии — по снимку, исполнение — после перечитывания (RM4-2).
6. **Правила Brave (RM4-10, PL-21):** частичная пересборка не теряет соседние значения; ребёнок без загруженной ветки (не входил) — запись через `viaProfile`; удаление программы снимает ветку; список «Запрещённых» > 1000 — отказ с текстом; сверка раз в 60 с не пишет журнал без расхождения.
7. **Обновление 0.3.3 → 0.4.0:** миграция 009 на заполненной базе 0.3.3 (тест по образцу `TestMigration007OnFilled006Base`): стартовый набор «Видео и соцсети» (R14) вставлен и при новой установке, и при обновлении; дубли `site_rules`, браузеры каталога → «Запрещено», `video_min` `NULL` → без лимита; слияние магазина один раз и идемпотентно.
8. **Приёмка и R23 (PL-16, PL-22, PL-41, PL-27):** тест, что журнал работы и журнал родителя не содержат адреса страницы (пути и параметров после домена); ждать текст плашки и счётчик журнала, а не окно; образцы — из ответа программы; новое тестовое действие проходит через `hTestGuard`; запасная ветка (подмена домена) исполняется хотя бы одним сценарием; ни одна страница не грузится из сети (hosts).
9. **Все экраны, где есть остаток видео:** значок (подсказка), «Сегодня» («Видео 10 мин из 20»), «Моя статистика», «Мои правила», копирование правил (FR-33) копирует видео-лимит, «Итоги» показывают видео.
10. **Ресурсы (NFR-4, NFR-5, ST2):** список «18+» не копируется в кучу; размер установщика ≤ 40 МБ проверяется в CI; проверка домена кэшируется по домену.
