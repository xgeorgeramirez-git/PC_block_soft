# План вехи M5 «Статистика для родителя и ребёнка» (версия 0.5.0)

> Оркестратор вехи исполняет план конвейером «два слота» (dev-methodology, раздел «Конвейер вехи»): один писатель за раз, читатель готовит пакет следующей задачи; реестр — `plans/M5-agents.md`; пакеты — `plans/packets/M5-T<N>-*.md`. План составлен заново в чате 10.11.2026: план прошлого чата (ветка `feature/m5-stats`, решения D-69, D-70) на GitHub не попал и потерян.

**Goal:** полная статистика у родителя и в окне ребёнка: «По дням» столбиками с линией лимита дня, превышениями и доп. временем (за год и всё время — по месяцам), таблицы «Программы» и «Сайты» за период, «Нарушения» и история «Копилки» за период, журнал с фильтрами по ребёнку, типу и периоду; база выдерживает 3 года на 3 детей (ST1).

**Architecture:** служба при каждой записи дня запоминает лимиты этого дня (миграция 010: снимок лимита в `day_state`, у старых дней «лимит неизвестен», D-70); хранилище отдаёт ряды по дням и по месяцам, учёт за период и события с фильтрами прямо запросом; служба собирает столбики (сегодня — из ядра, прошлые дни — из базы строго до сегодня, PL-31) и отдаёт их в том же ответе «Моей статистики», что и «Итоги» (один источник у ребёнка и родителя); окно рисует столбики своим компонентом без сторонних библиотек.

**Tech Stack:** Go 1.27 (служба, ядро — стандартная библиотека), SQLite (modernc), Wails v2 + React/TS/Vite, PowerShell-приёмка на windows-latest, Playwright-снимки на ubuntu.

**Спека:** `docs/01_ТЗ.md` 1.20 (после задачи T0) — R21, R22, FR-12, FR-23, FR-24, разделы 4 (`day_state`), 8.2.6, 8.3.7, 9 (M5), 10 (ST1), 11 (S21, S22, S47); решения D-12, D-26, D-44, D-47, D-58, D-61, D-63, D-64, **D-69**, **D-70**; эталон **G15** (эталонная неделя).

**Ветка:** `feature/m5-stats` от main после выпуска 0.4.0. Дерево `/home/claude/pc_block_soft`.

## Решения оркестратора (Ruling, действуют, пока заказчик не изменит)

- **RM5-0. Среда этого чата.** Сеть для команд закрыта: npm-пакеты не ставятся (фронт проверяет только `ci.yml`), Go 1.27 не скачивается. Локально работает Go 1.24 с подменённым файлом модуля для пакетов на стандартной библиотеке: `sed 's/^go 1.27.*/go 1.24/; /^toolchain/d' go.mod > /tmp/local.mod && cp go.sum /tmp/local.sum && GOTOOLCHAIN=local GOFLAGS=-mod=mod GOPROXY=off go test -race -count=1 -modfile=/tmp/local.mod ./internal/core/... ./internal/service/ ./internal/ipc/... ./internal/programs/...` (проверено 10.11.2026: зелёные). Хранилище (SQLite) локально не собирается — только `ci.yml`. `internal/sites` локально падает на `TestAdultNoCopy` (число выделений памяти зависит от версии Go) — не считать. Если в коде понадобится функция стандартной библиотеки новее Go 1.24, локальная проверка пакета невозможна — Ruling писателя, проверка в `ci.yml`. Цена: петля хранилища и фронта — через push; поэтому задачи T1, T5, T6 сдаются крупными, с полным набором тестов до push.
- **RM5-1. Снимок лимита дня (D-70).** Миграция 010 добавляет в `day_state`: `limit_known INTEGER NOT NULL DEFAULT 0`, `limit_total_min INTEGER`, `limit_games_min INTEGER`, `limit_video_min INTEGER` (NULL — без лимита). Старые строки получают `limit_known = 0` — «программа тогда не запоминала лимит». С 0.5.0 каждая запись дня службой (`SaveDayState`, `SaveDayAndUsage`) пишет `limit_known = 1` и лимиты **дня недели даты `st.Day`** (не текущего момента: день, закрытый в полночь `service.go` `afterDecision` → `saveState`, и вчерашний день после перезапуска B-42 пишутся уже после полуночи); индекс правил: `Week[0]` — понедельник, а в Go `time.Weekday` 0 — воскресенье, поэтому `(int(weekday)+6)%7`. Последняя запись дня остаётся — сохраняется лимит, действовавший в конце дня (изменение лимита днём меняет линию этого дня; согласуется с табло ребёнка). При `cs.rules.Broken` служба передаёт `Limit = nil`, а запрос записи **не затирает** уже запомненный лимит: `limit_known = max(limit_known, excluded.limit_known)`, колонки лимита — `CASE WHEN excluded.limit_known = 1 THEN excluded.… ELSE day_state.… END`. День, у которого лимит так и не запомнился из-за сбоя правил, показывается как старый (без линии, под общей строкой RM5-3) — цена: строка «до версии 0.5.0» для такого редкого дня неточна, сбой правил и так пишется в журнал. `core.DayState` получает поле `Limit *core.DayLimit` (тот же тип, что в правилах; nil — не запомнен); ядро его только переносит. Тест: день пт, закрытый в 00:00:05 сб, получает лимит пятницы.
- **RM5-2. Разбивка столбиков (D-69).** «Сегодня» — один столбик (сегодня); «Неделя» — по дню с понедельника по сегодня; «Месяц» — по дню с 1-го числа по сегодня; «Год» — по месяцу с января по текущий месяц; «Всё время» — по месяцу с первого месяца, где есть данные, по текущий. Дни и месяцы без данных внутри диапазона — нулевые столбики (календарь без дыр); у дня без строки в базе линии нет (компьютер не включали — лимит не запоминался), но он не «неизвестный» и строку про 0.5.0 не вызывает. Подпись дня — «пн 16», месяца — «ноя»; если «Всё время» захватывает несколько лет — «ноя 2025».
- **RM5-3. Линия лимита и превышение.** Столбик дня — общее время в счёт лимита (`total_s`; учёба отдельным сегментом поверх, подписана, D-7). Линия — общий лимит дня без доп. времени (`limit_total_min`), если лимит известен и задан; «Без лимита» и неизвестный лимит (D-70) — без линии. **Превышение** — день с известным лимитом, в котором общее время больше лимита не меньше чем на 60 с (`total_s − limit·60 ≥ 60`; меньше — округление последней минуты, не превышение; один порог `overMinS = 60` в Go, тесты берут его литералом); причина — доп. время, копилка, промокод или последняя минута по часам; часть столбика выше линии выделена, у дня метка «+N мин сверх лимита» (N — целые минуты вниз). Дни с доп. временем отмечены знаком и подписью «доп. время +N мин» (8.2.6 п.4). У месячного столбика линии нет (у месяца нет одного лимита); подпись месяца — «превышений: N дн., доп. время: N дн.». Если в ряду есть дни с неизвестным лимитом — под графиком одна строка: «Для дней до версии 0.5.0 лимит не показан: тогда программа его не запоминала». Определение превышения — **вопрос заказчику Q-M5-1** в отчёте (по умолчанию — как здесь).
- **RM5-4. Один ответ на период, одно чтение дней.** `MyTodayReply` получает `Bars []DayBar`, `BarsBy` («day»|«month»), `LimitUnknown bool`, `Violations []JournalEntry` (нарушения ребёнка за период, новые сверху, не больше 200), `Bonus []BonusRecord` (сырые записи копилки за период — `atMs`, `deltaMin`, `reason`, `balanceAfter` — новые сверху, не больше 200; текст строки собирает тот же `frontend/src/lib/bonus.ts`, что на экране «Копилка», — один текст в одном месте). Один запрос на смену периода (NFR-13); «Программы» и «Сайты» строятся из уже существующего `Programs` (поле `Kind`), доля — от суммы своей таблицы, самые долгие сверху (как вкладки D-58; доли округляются по отдельности, сумма может быть 99 % или 101 %). **«Итоги» и столбики — из одного чтения** `DaysSeries` за период (≤ 1100 строк за 3 года): служба в Go суммирует «Итоги», строит столбики дней и месяцев и считает превышения; `PeriodDays` больше не вызывается из `myTodayOf` (остаётся в хранилище для совместимости, пока не удалит ревью); ошибка чтения — и «Итоги», и столбики только за сегодня (класс A, PL-28). Правило превышения — одно, в Go (`buildBars`), в SQL его нет.
- **RM5-5. Журнал с фильтрами (FR-24).** Фильтр уходит в базу: `EventFilter` получает `FromMs`, `ToMs`, `Kinds []string`, курсор `BeforeAtMs`/`BeforeID` (страница по 200, кнопка «Показать ещё»); индекс `events(child_id, at)` и `events(at)` в миграции 010. Тип — группа событий из одной таблицы службы `journalGroups` рядом с `journaltext.go`: «Нарушения» (`bypass`, `program_forbidden_try`, `site_forbidden_try` — тот же набор, что `VIOLATION_KINDS` фронта), «Время» (доп. время, пауза, копилка, промокоды, перерыв), «Программы и сайты» (решения, «ждут решения», закрытия, списки сайтов, правила Brave), «Пароль и настройки», «Работа программы» (ошибки службы, восстановление базы). Вкладки периода журнала остаются D-47: «Сегодня», «За месяц», «Всё»; ребёнок — «Все дети» или один. Все виды событий, которые пишут служба и ядро, сводятся в один перечень `internal/service/eventkinds.go` (`ev*`-константы; строковые литералы видов в коде записи — `settings_changed`, `bonus_grant`, `bonus_reduce`, `bonus_clear`, `bonus_undo`, `promo_create`, `children_changed`, `rest_break`, `safe_mode`, `day_closed`, `no_forbidden`, `child_admin`, `child_admin_off` и др. — заменяются константами). Тест-разбор исходников (`go/parser` по `internal/service` и `internal/core`, без тестовых файлов) находит каждое место записи события — в ядре это литералы событий с полем `Kind:`, в службе — вызовы записи в журнал; если вид передан переменной (`Write(…, kind)`, `Write(…, e.Kind)`), тест прослеживает присваивания этой переменной/полю в той же функции и требует констант из перечня, а неразрешимое место — только с пометкой-исключением `//eventkind:dynamic <откуда вид>` и отдельным тестом этого места; итог — вид всегда константа из перечня, а каждая константа перечня — ровно в одной группе (мутации «убрать вид из группы» и «новый литерал вида» красные). `child_admin`/`child_admin_off` (отметка «детская» снята или учётка стала администратором, R1) — «Пароль и настройки», не нарушение. Вид в базе, которого нет в перечне (запись старой версии), показывается только в «Все события».

## UX-сценарий

Родитель: «Статистика» → ребёнок «Миша» → период «Неделя». Видит «Итоги» (как сейчас), ниже «По дням»: семь столбиков пн…вс, на каждом — время, пунктирная линия лимита дня; вторник выше линии, его верх выделен, подпись «+20 мин сверх лимита», значок доп. времени «+30 мин»; суббота без линии и под графиком строка про дни до 0.5.0. Наводит или фокусирует столбик → подсказка «вт, 17 ноября: 2 ч 20 мин из 2 ч, доп. время +30 мин, учёба 0 мин» (формат подсказки: «<день>: <время> из <лимит>[, доп. время +N мин], учёба <N мин>»; без лимита — «<время>, без лимита»; не запомнен — только «<время>»). Ниже «Программы» и «Сайты» — таблицы «название — время — доля», «Нарушения» — «когда — что», «Копилка» — баланс и история. Переключает «Год» → столбики по месяцам январь…ноябрь, без линии, подписи «превышений: 2 дн.». Пустой период — «За этот период пока нет данных». Ошибка загрузки — уведомление и «Повторить»; прошлые данные экрана при этом не смешиваются с новыми (поздний ответ прошлого периода не перекрывает выбранный — как сейчас `seq`).

Ребёнок: значок → «Моя статистика» → те же разделы о себе, только просмотр, без выбора ребёнка и без полей ввода (S22).

Родитель: «Журнал» → вкладки «Сегодня / За месяц / Всё», над списком «Ребёнок: все дети ▾» и «Что: все события ▾»; выбрал «Нарушения» → только нарушения; внизу «Показать ещё», если есть старые. Ничего не нашлось — «За этот период таких событий нет». Ссылка «Нарушения сегодня» с главной открывает журнал с типом «Нарушения» и периодом «Сегодня».

Доступность: столбики — `role="img"` с подписью итога и скрытая для глаз таблица тех же цифр (читалка экрана); подсказка столбика открывается и с клавиатуры (фокус); цвета различаются не только цветом (линия пунктиром, превышение штриховкой, доп. время значком); окно не прокручивается целиком (PL-25), график живёт в своей области.
