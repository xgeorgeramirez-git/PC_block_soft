## Review Focus (классы уроков + спека)
1. Расчёты и периоды (D): автобонус R25 — формула `N×(остаток div 10)`, дно 0, потолок копилки 600, граница суток (начисление в 00:00 за прошедший день), однократность за день (`bonus_granted`), «полностью запретный день → без бонуса». Эталоны-таблицы обязательны (golden).
2. Согласованность представлений (A): промокод и «снять запрет на сегодня» меняют остаток/статус — карточка родителя, значок, экран блокировки, мини-панель, «Моя статистика» должны показывать согласованно.
3. Приёмка (E): промокод одноразовый — повторный ввод не добавляет; ввод на двух экранах (блокировка + «Бонусы») даёт один и тот же результат; «снять запрет» сбрасывается на следующий день.
4. Подсветки/подсказки (B): помощник — покрытие новых элементов (убавление/обнуление копилки, промокоды, снятие запрета, настройка бонуса, вкладка «Бонусы»); «Что нового» N-0.2.2.
5. Безопасность по умолчанию: снятие запрета/промокод не ослабляют аварийный выход (экран блокировки и пароль остаются); ввод промокода не обходит пароль родителя для настроек.

- Редактор запретного интервала: при открытии «правка» поля «с…/до…» заранее заполнены текущими значениями интервала.
- TDD: vitest — ввод букв/«99 минут» отбивается/зажимается; правка интервала показывает текущие числа.

## FB-5 — автоматические бонусы (R25, D-49)
**Зона:** internal/core (начисление), internal/storage (`bonus_granted`, `bonus_min_per_10`), internal/service (прогон начисления на смене суток), frontend («Бонусы» + настройка).
- core: функция начисления за прошедший день `GrantDailyBonus(child, day)` — считает остаток за день (`лимит+доп − общее`, ≥0), `bonus = N × (остаток div 10)`, где N из настройки (деф. 5); пропускает дни «игра не была разрешена» (лимит 0 или день полностью в запретных интервалах); зажимает по потолку копилки 600; ставит `bonus_granted=1`, пишет `bonus_ledger` (reason «Бонус за свободное время: K мин»). Идемпотентно (если `bonus_granted=1` — ничего). **Эталон — golden-таблица** (несколько дней с разными остатками/лимитами/интервалами → ожидаемый бонус), тесты на поддельных часах.
- storage: столбцы `day_state.bonus_granted`, настройка `bonus_min_per_10` (деф. 5); миграция `NNN_bonus.sql`.
- service: на пересечении полуночи (или при первом тике нового дня) прогнать начисление за вчера по каждому ребёнку; интеграционный тест на ускоренных часах.
- frontend: вкладка «Бонусы» у ребёнка («Моя статистика»→«Копилка/Бонусы») и у родителя (экран «Копилка») — простым языком «За то, что не всё время потратил, начислено K мин»; настройка «Бонус за неизрасходованное время: N минут за каждые 10 минут» в Настройках.
- TDD: core golden (формула, дно, потолок, запретный день, округление вниз), storage (миграция/флаг/настройка), service (начисление ровно раз на смене суток), frontend.

## FB-6 — промокоды на время (R26, FR-35, D-50)
**Зона:** internal/core (применение кода к сегодняшнему дню = +extra_min всем лимитам), internal/storage (`promo_codes`), internal/ipc/service (создать/список/применить; применение — childSelf, создание/список — родитель), frontend (экран «Копилка/Бонусы» у родителя: создание + списки; ввод у ребёнка — экран блокировки 8.2.3 и раздел «Бонусы»).
- storage: таблица `promo_codes` (code_norm UNIQUE, code_display, minutes, created_at, used_at, used_by_child); миграция.
- core/service: `CreatePromo(code, minutes)` (родитель), `ListPromo()` (действующие/использованные, родитель), `RedeemPromo(child, code)` (childSelf): нормализовать код (trim+lower), найти действующий; есть → `extra_min += minutes` на сегодня (как доп. время, расширяет все три лимита), пометить used_at/used_by_child, журнал; нет/использован → ошибка «Код не подходит». Промокод НЕ выводит из запретного интервала (как доп. время).
- ipc: команды + TS-зеркало; статусы ошибки.
- frontend: у родителя в «Копилка/Бонусы» — форма создания (код + минуты) и два списка; у ребёнка поле «Ввести промокод» на экране блокировки (8.2.3) и в разделе «Бонусы».
- TDD: core (применение добавляет время всем лимитам; одноразовость), storage (уникальность кода, пометка использования), ipc contract, frontend (создание, списки, ввод на двух экранах, «Код не подходит»).
- Review Focus: одноразовость (повторный ввод — отказ), ввод на двух экранах даёт один результат, код без регистра/пробелов.

## FB-7 — снять запрет «не игрового времени» на день (R24, D-51)
**Зона:** internal/core (учёт `no_forbidden` в правиле запретных интервалов), internal/storage (`day_state.no_forbidden`), internal/ipc/service (команда, родитель), frontend (карточка «Сегодня» FR-15).
- core: при `no_forbidden=1` для сегодняшней даты запретные интервалы (R7) не применяются; общий лимит/игры/видео (R4–R6) действуют как обычно. Сбрасывается сменой даты (флаг привязан к `day`).
- ipc/service: команда `SetNoForbiddenToday(child, on)` (родитель); TS-зеркало.
- frontend: кнопка «Снять запрет на сегодня» на карточке ребёнка; когда снято — видно и есть «Вернуть».
- TDD: core (в запретный интервал при `no_forbidden=1` блокировки нет, но лимит времени действует; завтра запрет снова), ipc, Today.test.
