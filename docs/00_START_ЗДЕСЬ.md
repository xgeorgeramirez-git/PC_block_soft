# СТАРТ ЗДЕСЬ — контекст для ИИ-агента-разработчика

Ты пишешь PC_block_soft — программу родительского контроля для Windows 11 — для заказчика-родителя (не программист, общение по-русски, простыми словами; технические подробности — в файлах репозитория). Истории переписки у тебя нет: весь контекст в репозитории.

Читай в порядке:
1. `docs/01_ТЗ.md` — ТЗ (FR, NFR, R, S, ST, вехи M1…M7).
2. `docs/02_Концепт.md` — зачем и как (разделы 4.3 и 4.5 обязательно).
3. `docs/03_Решения_интервью.md` — решения заказчика D-N, формулировки дословно (read-only).
4. `docs/04_Эталоны_учёта.md` — эталоны G1…G12 (истина в последней инстанции).
5. `docs/06_Приёмка.md` — чек-лист приёмки.
6. `CLAUDE.md` — память проекта (правила, грабли, состояние); `SKILLS.md` — какие скиллы грузить.
7. `docs/LESSONS.md` — уроки этого проекта; межпроектные — `references/lessons.md` скилла dev-methodology.
8. `plans/PROMPTS.md` — промт твоей вехи.

## Что ты делаешь
Вехи M1…M7 по порядку, по одной на чат. Методология dev-methodology: план вехи → TDD → тест-серия по лестнице R0–R4 в CI → ревью свежим субагентом → приёмка S-сценариями со скриншотами в ветке `screenshots` → закрытие вехи (README, память, уроки, версия).

## Жёсткие правила
1. Решения заказчика (`docs/03_Решения_интервью.md`) и эталоны — read-only; менять только по новому решению заказчика.
2. Эталоны G1…G12 — истина: расхождение расчёта с эталоном = ошибка твоего кода.
3. Стек зафиксирован в ТЗ, раздел 3; смена — только с обоснованием в README «Отклонения от ТЗ».
4. Форматы: длительности — целые секунды в базе; даты дня `YYYY-MM-DD` по местному времени; моменты — UTC мс + смещение пояса; UTF-8 везде.
5. Никакой сети: ноль сетевых соединений, ни аккаунтов, ни телеметрии, ни автообновлений (NFR-1, NFR-2). Никакой слежки: скриншоты, переписка, нажатия клавиш, адреса страниц, заголовки окон не собираются (R23).
6. Аварийный выход в каждой версии: экран блокировки всегда принимает родительский пароль, учётки родителя и администраторов никогда не ограничиваются (NFR-10, R18).
7. Блокировки испытываются только в CI на windows-latest в тестовом режиме. Никаких запусков блокировок на компьютере заказчика без его явного согласия.
8. Тексты интерфейса — русские, ребёнку на «ты», родителю на «вы», без длинных тире, без технических текстов ошибок. Стиль — сдержанный, без «AI-вида» (ТЗ 8.0).
9. Отклонения от ТЗ — в README «Отклонения от ТЗ», не молча.
10. Тестирование не опция: нет падающего теста — нет кода; «готово» без зелёной серии в CI = не готово. Тяжёлые прогоны на windows-latest — строго по лестнице R0–R4 (минуты Windows в приватном репозитории дороже).
11. Мёржи в main делает агент сам; force-push, удаление данных и изменения вне репозитория — только с согласия заказчика.
