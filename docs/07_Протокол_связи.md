# Протокол связи компьютера и телефона (M7, FR-40, NFR-1, NFR-16)

Версия 1 (уточнена ревью плана 18.11.2026). Общий договор для трёх частей: сервер связи `cmd/pcblock-relay` (VPS), пакет службы `internal/remote` (компьютер), приложение `android/` (телефон) и тестовый телефон `tools/remote-phone`.

## 1. Роли и доверие

- **Сервер связи** — почтовый ящик: хранит учётные записи компьютеров и телефонов (только хэши токенов), передаёт сообщения между ними, помнит последний отчёт компьютера и время последнего опроса. Содержимое сообщений он **не понимает и не проверяет** (кроме размера).
- **Компьютер** доверяет только подписи телефона, ключ которого родитель подтвердил при привязке (сверка числа, раздел 4). Телефон доверяет только подписи компьютера, ключ которого он подтвердил так же.
- Взломанный сервер может: не передавать сообщения, задерживать их (не дольше срока команды), показывать «Нет связи». Не может: подать команду от имени телефона, подменить остаток, подставить свой ключ при привязке незаметно для родителя.

## 2. Ключи и подписи

- Алгоритм — **ECDSA P-256 + SHA-256** (Android Keystore умеет его с API 23 аппаратно; Go — `crypto/ecdsa`). Подпись — ASN.1 DER (`ecdsa.SignASN1`/`VerifyASN1`, Java `SHA256withECDSA`).
- Открытый ключ передаётся как SubjectPublicKeyInfo DER (`x509.MarshalPKIXPublicKey`, Java `PublicKey.getEncoded()`), в JSON — base64url без `=`.
- В каждом подписанном JSON есть поле типа `"t"`: `"cmd"`, `"cmdr"`, `"report"` — подпись одного типа нельзя выдать за другой; получатель отклоняет чужой тип.
- Подписанный блок: `{"data": "<base64url байтов JSON>", "sig": "<base64url DER>"}`. Подписываются **байты `data`** как есть; получатель сначала проверяет подпись, потом разбирает JSON из `data`. Канонизации JSON нет.
- Все base64 в протоколе — base64url без дополнения `=`.

## 3. HTTP-интерфейс сервера

Все запросы и ответы — JSON, `Content-Type: application/json`, тело не больше 16 КБ (больше — 413). Ошибка — код HTTP и `{"error": "<код>"}` (коды ниже), текст для человека делает клиент. Авторизация — `Authorization: Bearer <токен>`. Время сервера в каждом ответе — `serverNowMs` (UTC мс).

| Метод и путь | Кто | Тело запроса | Ответ 200 |
|---|---|---|---|
| `GET /healthz` | любой | — | `{"ok":true}` |
| `POST /v1/pc/register` | компьютер (без токена) | `{}` | `{"pcId","pcToken"}` |
| `POST /v1/pc/pair-code` | компьютер | `{}` | `{"code":"123456","expiresMs"}` (10 мин; прежний код этого компьютера погашен) |
| `GET /v1/pc/poll?wait=25` | компьютер | — | `{"messages":[Msg…]}`; ждёт до `wait` секунд (≤ 25), пока нет сообщений; отмечает «компьютер на связи» |
| `POST /v1/pc/reply` | компьютер | `{"to":"<phoneId>","replyTo":"<msgId>","kind","body"}` | `{}` |
| `POST /v1/pc/report` | компьютер | `{"body": Signed}` | `{}` — последний отчёт хранится в памяти |
| `POST /v1/pc/unpair` | компьютер | `{"phoneId"}` | `{}` — токен телефона погашен |
| `POST /v1/phone/pair` | телефон (без токена) | `{"code","kind":"pair1","body"}` | `{"pcId","phoneId","phoneToken","reply":Msg}` |
| `POST /v1/phone/send` | телефон | `{"kind","body"}` | `{"reply":Msg}` |
| `GET /v1/phone/status` | телефон | — | `{"pcLastSeenMs","report":Signed\|null}` |

`Msg` = `{"id":"<случайный>","from":"<phoneId>","kind":"…","body":<JSON>}`.

Сервер, получив `phone/pair` или `phone/send`, кладёт `Msg` в очередь компьютера и **ждёт ответа компьютера** (`pc/reply` с `replyTo = id`) до 10 с; нет ответа — 504 `pc_offline`, и сообщение сразу удаляется из очереди, если опрос ещё не забрал его. Сообщение в очереди живёт не дольше ожидания ответа (10 с): команда, про которую телефону сказали «не отправлено», не применится позже (FR-40, команды не копятся). Очередь компьютера — не больше 32 сообщений (больше — 503 `busy`).

Коды ошибок: `internal` (500, сбой записи файла сервера), `bad_request` (400), `unauthorized` (401), `bad_code` (403, код неверный или истёк), `too_many` (429, ограничение), `pc_offline` (504), `busy` (503), `too_large` (413), `not_found` (404).

Ограничения сервера: `phone/pair` — 5 неверных кодов с одного адреса или на один компьютер за 10 мин → 429 до конца окна (неверный код засчитывается адресу и каждому компьютеру с действующим кодом, истёкший — адресу и своему компьютеру); код одноразовый: погашен первым `pair1`, при 504 возвращается, если компьютер `pair1` не получил (опрос его не выдал), код не истёк и не выпущен новый; `pair1` принимается только через `phone/pair` (`phone/send` с `kind:"pair1"` — 400 `bad_request`); записей телефонов на компьютер не больше 5 (лишняя — самая старая удаляется); опрос отдаёт не больше ~48 КБ сообщений за раз (по закодированным байтам; ответы без экранирования `<>&`), остальное — следующим опросом; «на связи» отмечает любой запрос компьютера; `pc/register` — 10 в час с адреса и компьютеров на сервере не больше 20 (иначе 429 `too_many`); компьютер, не выходивший на связь 30 дней, удаляется вместе с его телефонами, а зарегистрированный и ни разу не вышедший на связь — через сутки после регистрации (память сервера: после перезапуска такие записи живут по правилу 30 дней) (`lastSeen` пишется в файл не чаще раза в час); адрес клиента — из `X-Forwarded-For` (последний элемент), только если сервер запущен с `-trust-proxy` (за Traefik). Журнал сервера — без токенов, кодов и тел сообщений.

Хранение: файл `/data/relay.json` (компьютеры: `pcId`, SHA-256 токена, `lastSeenMs`; телефоны: `phoneId`, `pcId`, SHA-256 токена), запись атомарно (временный файл + rename). Очереди, коды, отчёты и «на связи» — только в памяти: после перезапуска сервера компьютер присылает отчёт заново в течение минуты.

## 4. Привязка телефона (сверка числа)

Короткий код из 6 цифр сам по себе не защищает от сервера: сервер его видит. Поэтому ключи сверяются числом на обоих экранах, а обязательство (commit) не даёт серверу подобрать свои ключи под совпадающее число.

1. Родитель: «Подключить телефон» → компьютер `pc/pair-code` → окно показывает код.
2. Телефон создаёт пару ключей и шлёт `phone/pair {code, kind:"pair1", body:{"phonePub","name"}}`.
3. Компьютер (из опроса) создаёт случайный `nPc` (16 байт) и отвечает `pc/reply kind:"pair1r" body:{"pcPub","commit"}`, где `commit = SHA-256("pcblock-commit-v1" ‖ pcPubDER ‖ phonePubDER ‖ nPc)`.
4. Телефон создаёт случайный `nPhone` (16 байт) и шлёт `phone/send kind:"pair2" body:{"nPhone"}`.
5. Компьютер отвечает `kind:"pair2r" body:{"nPc"}`. Телефон проверяет `commit` (не сошлось — привязка прервана, «Не удалось подключить. Попробуйте ещё раз»).
6. Оба считают **число сверки**: первые 4 байта `SHA-256("pcblock-sas-v1" ‖ pcPubDER ‖ phonePubDER ‖ nPc ‖ nPhone)` как беззнаковое big-endian, по модулю 1 000 000, шесть цифр с ведущими нулями, показывается «123 456».
7. Окно родителя: «На телефоне должно быть число 123 456» и кнопки «Совпадает» / «Не совпадает». Телефон показывает то же число и «Нажмите «Совпадает» на телефоне и на компьютере».
8. «Совпадает» на компьютере: телефон записан привязанным (прежний телефон отвязан: `pc/unpair`, D-92), журнал «Телефон подключён». «Совпадает» на телефоне: ключ компьютера записан. «Не совпадает» или 10 мин без ответа на любой стороне — привязка отменена, ключи забыты.

**Порядок строгий (конечный автомат компьютера):** `idle` → (`pair-code`) `code` → (первый `pair1` с верным кодом; код сразу погашен на сервере и в памяти компьютера) `wait_nonce` → (единственный `pair2` от того же `phoneId`) `compare` → («Совпадает») `done` или («Не совпадает», 10 мин) `idle`. Любое другое сообщение на этапе привязки — второй `pair1`, второй `pair2`, `pair2` от чужого `phoneId`, `pair2` до `pair1r` — **отменяет привязку** (иначе сервер, узнав `nPc`, подобрал бы `nPhone` под нужное число). Отменённая или истёкшая привязка: компьютер вызывает `pc/unpair` для этого `phoneId` (токен «брошенного» телефона погашен). Новая привязка сбрасывает `LastSeq` в 0 (у нового телефона счёт с 1).

Строки-метки (`"pcblock-commit-v1"`, `"pcblock-sas-v1"`) — байты UTF-8, `‖` — склейка байтов.

## 5. Команды с телефона

`phone/send kind:"cmd" body: Signed`, `data` = JSON:

```json
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":17,"ts":1763490000000,"child":3,"delta":15}
```

- `delta` — минуты доп. времени: `+N` — добавить, `−N` — убавить, 1 ≤ |N| ≤ 240 (R10, `core.MaxExtraMin`).
- Компьютер принимает команду, только если: подпись верна ключом привязанного телефона; `pc` — свой; `phone` — привязанный; `seq` больше последнего принятого (хранится в настройках); `|ts − часы компьютера| ≤ 5 мин` по настоящим часам службы (`RealNow`, не по часам ядра — в тестовом режиме они ускорены); повтор отсекает `seq` при любых часах. Номер `seq` записывается до применения и одной блокировкой службы с ним: команда применяется не больше одного раза, даже при сбое посередине.
- Ответ `kind:"cmdr" body: Signed`, `data` = `{"v":1,"t":"cmdr","pc","phone","seq":17,"cmd":"<base64url SHA-256 байтов data команды>","ts","ok":true,"message":"Добавлено 15 минут","report":Report}` или `{…,"ok":false,"error":"<код>","lastSeq":16}`; телефон принимает ответ, только если `cmd` — хэш его команды; коды: `bad_sig`, `replay`, `stale`, `no_child`, `range`, `not_paired`. Отклонённая команда в журнал родителя не пишется (S55), только в журнал работы службы без подробностей.
- Применение — те же правила, что у кнопок окна родителя (R10): предел, плашка ребёнку (D-93), запись журнала «Миша: вы добавили 15 мин с телефона» / «Миша: вы убавили 15 мин с телефона» (при «−» — фактически убранные минуты). «Отменить» для команды с телефона нет (у телефона есть «−»), и команда не стирает «Отменить» окна. Тексты телефона на отказ: `replay`/`stale` — «Команда устарела, повторите», `not_paired`/`bad_sig` — «Телефон не подключён к этому компьютеру. Подключите заново», `no_child` — «Ребёнок не найден», `range` — «Можно от 1 до 240 минут».

## 6. Отчёт компьютера

`pc/report body: Signed`, `data` = Report:

```json
{"v":1,"t":"report","pc":"<pcId>","phone":"<phoneId>","ts":1763490000000,
 "children":[{"id":3,"name":"Миша","usedSec":3600,"leftSec":1800,"extraMin":15,"blocked":false}]}
```

- Отправляется: при включении связи, раз в 60 с, сразу после применённой команды и после привязки. `phone` — привязанный телефон (телефон проверяет, что отчёт для него, и отбрасывает отчёт с `ts` старше уже показанного). `leftSec` — то же «осталось», что показывает окно родителя.
- Телефон показывает «На связи», если `serverNowMs − pcLastSeenMs ≤ 60 000` (это только доступность: сервер может её исказить, но не данные), иначе «Компьютер не на связи с HH:MM» (по `pcLastSeenMs`, местное время телефона). Остаток показывается из последнего отчёта с подписью и подписью времени отчёта («данные на HH:MM»).

## 7. Поведение компьютера при обрывах (NFR-16)

- Две горутины на поколение связи: **опрос** (`pc/poll?wait=25`, тайм-аут клиента 35 с) и **отправка** (ответы, отчёты, `pair-code`, `unpair` — очередь заданий, не ждут конца опроса; код привязки появляется ≤ 2 с). Опрос: ошибка сети или 5xx — пауза с экспонентой 1, 2, 4 … 30 с ± 20 %; успешный опрос сбрасывает паузу. Восстановление после возврата сервера — не позже 30 с + 25 с ≤ 60 с.
- 401 с телом `{"error":"unauthorized"}` на опросе (сервер потерял запись компьютера) — повторная регистрация `pc/register`, привязка телефона сбрасывается (телефон увидит «нужно подключить заново»). Иной 401 (прокси, чужой сервис по адресу) — обычная ошибка с паузой: регистрация и привязка не трогаются.
- Связь выключена — контекст поколения отменён (идущий опрос обрывается), `CloseIdleConnections`, ни одного нового запроса (NFR-1). `Stop` не ждёт горутины (служба держит свою блокировку); запись состояния от старого поколения отбрасывается по номеру поколения. Транспорт — без прокси из окружения (`Proxy: nil`).
- 401 на опросе с привязанным телефоном — запись журнала «Телефон отвязан: сервер связи не узнал компьютер» и причина в окне.
- Только HTTPS; `http://` разрешён лишь для `127.0.0.1` и `localhost` в тестовом режиме службы (приёмка S55, S56).
- Сбой связи не трогает учёт, блокировки и стражей; ответы сервера больше 64 КБ, неверный JSON, чужой `pcId` — сообщение отброшено, строка в журнал работы с ограничителем частоты.
