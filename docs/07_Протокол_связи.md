# Протокол связи компьютера и телефона (M8, FR-40, NFR-1, NFR-16)

Версия 1.5 (18.11.2026; 19.11.2026 — сообщения, снятие запрета и статистика за сегодня, разделы 5а, 5б, 6; 26.11.2026 — стикер и звук сообщения, раздел 5а; 27.11.2026 — копилка, промокоды и решения о программах с телефона, разделы 5в, 5г, 5д, 6). Сервер связи для версии 1.5 не меняется: новые действия идут прежними `cmd`/`cmdr`, размеры — в пределах раздела 3. Общий договор для трёх частей: сервер связи `cmd/pcblock-relay` (VPS), пакет службы `internal/remote` (компьютер), приложение `android/` (телефон) и тестовый телефон `tools/remote-phone`.

## 1. Роли и доверие

- **Сервер связи** — почтовый ящик: хранит учётные записи компьютеров и телефонов (только хэши токенов), передаёт сообщения между ними, помнит последний отчёт компьютера и время последнего опроса. Содержимое сообщений он **не понимает и не проверяет** (кроме размера).
- **Компьютер** доверяет только подписи телефона, ключ которого родитель подтвердил при привязке (сверка числа, раздел 4). Телефон доверяет только подписи компьютера, ключ которого он подтвердил так же.
- Взломанный сервер может: не передавать сообщения, задерживать их (не дольше срока команды), показывать «Нет связи», **читать** отчёты и ответы (сообщения не шифруются, только подписываются: имена детей, статистика, промокоды, пути программ видны серверу — сервер стоит на VPS родителя). Не может: подать команду от имени телефона, подменить остаток, список промокодов или ждущих программ, подставить свой ключ при привязке незаметно для родителя, запросить список промокодов (запрос подписан телефоном и тратит `seq`).

## 2. Ключи и подписи

- Алгоритм — **ECDSA P-256 + SHA-256** (Android Keystore умеет его с API 23 аппаратно; Go — `crypto/ecdsa`). Подпись — ASN.1 DER (`ecdsa.SignASN1`/`VerifyASN1`, Java `SHA256withECDSA`).
- Открытый ключ передаётся как SubjectPublicKeyInfo DER (`x509.MarshalPKIXPublicKey`, Java `PublicKey.getEncoded()`), в JSON — base64url без `=`.
- В каждом подписанном JSON есть поле типа `"t"`: `"cmd"`, `"cmdr"`, `"report"` — подпись одного типа нельзя выдать за другой; получатель отклоняет чужой тип.
- Подписанный блок: `{"data": "<base64url байтов JSON>", "sig": "<base64url DER>"}`. Подписываются **байты `data`** как есть; получатель сначала проверяет подпись, потом разбирает JSON из `data`. Канонизации JSON нет.
- Все base64 в протоколе — base64url без дополнения `=`.

## 3. HTTP-интерфейс сервера

Все запросы и ответы — JSON, `Content-Type: application/json`, тело не больше 16 КБ (больше — 413). Ошибка — код HTTP и `{"error": "<код>"}` (коды ниже), текст для человека делает клиент. Авторизация — `Authorization: Bearer <токен>`. Время сервера в каждом ответе — `serverNowMs` (UTC мс).

| Метод и путь | Кто | Тело запроса | Ответ 200 |
|---|---|---|---|
| `GET /healthz` | любой | — | `{"ok":true}` |
| `POST /v1/pc/register` | компьютер (без токена) | `{}` | `{"pcId","pcToken"}` |
| `POST /v1/pc/pair-code` | компьютер | `{}` | `{"code":"123456","expiresMs"}` (10 мин; прежний код этого компьютера погашен) |
| `GET /v1/pc/poll?wait=25` | компьютер | — | `{"messages":[Msg…]}`; ждёт до `wait` секунд (≤ 25), пока нет сообщений; отмечает «компьютер на связи» |
| `POST /v1/pc/reply` | компьютер | `{"to":"<phoneId>","replyTo":"<msgId>","kind","body"}` | `{}` |
| `POST /v1/pc/report` | компьютер | `{"body": Signed}` | `{}` — последний отчёт хранится в памяти |
| `POST /v1/pc/unpair` | компьютер | `{"phoneId"}` | `{}` — токен телефона погашен |
| `POST /v1/phone/pair` | телефон (без токена) | `{"code","kind":"pair1","body"}` | `{"pcId","phoneId","phoneToken","reply":Msg}` |
| `POST /v1/phone/send` | телефон | `{"kind","body"}` | `{"reply":Msg}` |
| `GET /v1/phone/status` | телефон | — | `{"pcLastSeenMs","report":Signed\|null}` |

`Msg` = `{"id":"<случайный>","from":"<phoneId>","kind":"…","body":<JSON>}`.

Сервер, получив `phone/pair` или `phone/send`, кладёт `Msg` в очередь компьютера и **ждёт ответа компьютера** (`pc/reply` с `replyTo = id`) до 10 с; нет ответа — 504 `pc_offline`, и сообщение сразу удаляется из очереди, если опрос ещё не забрал его. Сообщение в очереди живёт не дольше ожидания ответа (10 с): команда, про которую телефону сказали «не отправлено», не применится позже (FR-40, команды не копятся). Очередь компьютера — не больше 32 сообщений (больше — 503 `busy`).

Коды ошибок: `internal` (500, сбой записи файла сервера), `bad_request` (400), `unauthorized` (401), `bad_code` (403, код неверный или истёк), `too_many` (429, ограничение), `pc_offline` (504), `busy` (503), `too_large` (413), `not_found` (404).

Ограничения сервера: `phone/pair` — 5 неверных кодов с одного адреса или на один компьютер за 10 мин → 429 до конца окна (неверный код засчитывается адресу и каждому компьютеру с действующим кодом, истёкший — адресу и своему компьютеру); код одноразовый: погашен первым `pair1`, при 504 возвращается, если компьютер `pair1` не получил (опрос его не выдал), код не истёк и не выпущен новый; `pair1` принимается только через `phone/pair` (`phone/send` с `kind:"pair1"` — 400 `bad_request`); записей телефонов на компьютер не больше 5 (лишняя — самая старая удаляется); опрос отдаёт не больше ~48 КБ сообщений за раз (по закодированным байтам; ответы без экранирования `<>&`), остальное — следующим опросом; «на связи» отмечает любой запрос компьютера; `pc/register` — 10 в час с адреса и компьютеров на сервере не больше 20 (иначе 429 `too_many`); компьютер, не выходивший на связь 30 дней, удаляется вместе с его телефонами, а зарегистрированный и ни разу не вышедший на связь — через сутки после регистрации (память сервера: после перезапуска такие записи живут по правилу 30 дней) (`lastSeen` пишется в файл не чаще раза в час); адрес клиента — из `X-Forwarded-For` (последний элемент), только если сервер запущен с `-trust-proxy` (за Traefik). Журнал сервера — без токенов, кодов и тел сообщений.

Хранение: файл `/data/relay.json` (компьютеры: `pcId`, SHA-256 токена, `lastSeenMs`; телефоны: `phoneId`, `pcId`, SHA-256 токена), запись атомарно (временный файл + rename). Очереди, коды, отчёты и «на связи» — только в памяти: после перезапуска сервера компьютер присылает отчёт заново в течение минуты.

## 4. Привязка телефона (сверка числа)

Короткий код из 6 цифр сам по себе не защищает от сервера: сервер его видит. Поэтому ключи сверяются числом на обоих экранах, а обязательство (commit) не даёт серверу подобрать свои ключи под совпадающее число.

1. Родитель: «Подключить телефон» → компьютер `pc/pair-code` → окно показывает код.
2. Телефон создаёт пару ключей и шлёт `phone/pair {code, kind:"pair1", body:{"phonePub","name"}}`.
3. Компьютер (из опроса) создаёт случайный `nPc` (16 байт) и отвечает `pc/reply kind:"pair1r" body:{"pcPub","commit"}`, где `commit = SHA-256("pcblock-commit-v1" ‖ pcPubDER ‖ phonePubDER ‖ nPc)`.
4. Телефон создаёт случайный `nPhone` (16 байт) и шлёт `phone/send kind:"pair2" body:{"nPhone"}`.
5. Компьютер отвечает `kind:"pair2r" body:{"nPc"}`. Телефон проверяет `commit` (не сошлось — привязка прервана, «Не удалось подключить. Попробуйте ещё раз»).
6. Оба считают **число сверки**: первые 4 байта `SHA-256("pcblock-sas-v1" ‖ pcPubDER ‖ phonePubDER ‖ nPc ‖ nPhone)` как беззнаковое big-endian, по модулю 1 000 000, шесть цифр с ведущими нулями, показывается «123 456».
7. Окно родителя: «На телефоне должно быть число 123 456» и кнопки «Совпадает» / «Не совпадает». Телефон показывает то же число и «Нажмите «Совпадает» на телефоне и на компьютере».
8. «Совпадает» на компьютере: телефон записан привязанным (прежний телефон отвязан: `pc/unpair`, D-92), журнал «Телефон подключён». «Совпадает» на телефоне: ключ компьютера записан. «Не совпадает» или 10 мин без ответа на любой стороне — привязка отменена, ключи забыты.

**Порядок строгий (конечный автомат компьютера):** `idle` → (`pair-code`) `code` → (первый `pair1` с верным кодом; код сразу погашен на сервере и в памяти компьютера) `wait_nonce` → (единственный `pair2` от того же `phoneId`) `compare` → («Совпадает») `done` или («Не совпадает», 10 мин) `idle`. Любое другое сообщение на этапе привязки — второй `pair1`, второй `pair2`, `pair2` от чужого `phoneId`, `pair2` до `pair1r` — **отменяет привязку** (иначе сервер, узнав `nPc`, подобрал бы `nPhone` под нужное число). Отменённая или истёкшая привязка: компьютер вызывает `pc/unpair` для этого `phoneId` (токен «брошенного» телефона погашен). Новая привязка сбрасывает `LastSeq` в 0 (у нового телефона счёт с 1).

Строки-метки (`"pcblock-commit-v1"`, `"pcblock-sas-v1"`) — байты UTF-8, `‖` — склейка байтов.

## 5. Команды с телефона

`phone/send kind:"cmd" body: Signed`, `data` = JSON:

```json
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":17,"ts":1763490000000,"child":3,"delta":15}
```

- `delta` — минуты доп. времени: `+N` — добавить, `−N` — убавить, 1 ≤ |N| ≤ 240 (R10, `core.MaxExtraMin`).
- Компьютер принимает команду, только если: подпись верна ключом привязанного телефона; `pc` — свой; `phone` — привязанный; `seq` больше последнего принятого (хранится в настройках); `|ts − часы компьютера| ≤ 5 мин` по настоящим часам службы (`RealNow`, не по часам ядра — в тестовом режиме они ускорены); повтор отсекает `seq` при любых часах. Номер `seq` записывается до применения и одной блокировкой службы с ним: команда применяется не больше одного раза, даже при сбое посередине.
- Ответ `kind:"cmdr" body: Signed`, `data` = `{"v":1,"t":"cmdr","pc","phone","seq":17,"cmd":"<base64url SHA-256 байтов data команды>","ts","ok":true,"message":"Добавлено 15 минут","report":Report}` или `{…,"ok":false,"error":"<код>","lastSeq":16}`; телефон принимает ответ, только если `cmd` — хэш его команды; коды: `bad_sig`, `replay`, `stale`, `no_child`, `range`, `not_paired`; для разделов 5г, 5д — ещё `promo_exists`, `promo_gen`, `not_found`. Отклонённая команда в журнал родителя не пишется (S55), только в журнал работы службы без подробностей.
- Применение — те же правила, что у кнопок окна родителя (R10): предел, плашка ребёнку (D-93), запись журнала «Миша: вы добавили 15 мин с телефона» / «Миша: вы убавили 15 мин с телефона» (при «−» — фактически убранные минуты). «Отменить» для команды с телефона нет (у телефона есть «−»), и команда не стирает «Отменить» окна. Тексты телефона на отказ: `replay`/`stale` — «Команда устарела, повторите», `not_paired`/`bad_sig` — «Телефон не подключён к этому компьютеру. Подключите заново», `no_child` — «Ребёнок не найден», `range` — «Можно от 1 до 240 минут».

## 5а. Сообщение с телефона (FR-41)

`phone/send kind:"note" body: Signed`, `data` = JSON:

```json
{"v":1,"t":"note","pc":"<pcId>","phone":"<phoneId>","seq":18,"ts":1763490000000,"child":3,"id":"<16 байт base64url>","text":"Иди ужинать","showSec":0,"sticker":"033","sound":2}
```

- `text` — 1…300 знаков Unicode (после обрезки пробелов по краям), переводы строк допустимы (не больше 5); `showSec` — 0 (пока не нажмёт «Понял»), 10, 30 или 60; `id` — случайный идентификатор сообщения от телефона; `sticker` — номер стикера из трёх цифр (`assets/stickers/<номер>.tgs`), нет поля — без стикера; `sound` — 0 (без звука) или номер звука 1…99 (`assets/sounds/message/<номер>.mp3`), нет поля — 1. Номер стикера или звука, которого нет в этой версии программы, — не ошибка: окно без стикера, звук 1 (набор телефона может быть новее). Ошибка `range` — только неверный вид: `sticker` не из трёх цифр, `sound` не целое 0…99.
- Проверки компьютера — как у команды (раздел 5: подпись, `t`, `pc`, `phone`, `ts`, `seq` в одной нумерации с командами), плюс длина текста и `showSec` (ошибка `range`).
- Ответ `kind:"noter"` — подписанный, как `cmdr` (`t:"noter"`, `seq`, `cmd` — хэш данных сообщения, `ok`, `error`); `ok:true` значит «принято», не «показано».
- Состояние сообщений — в отчёте (раздел 6): `"notes":[{"id","child","state":"queued|shown|read|expired","atMs"}]` — последние 10 сообщений не старше суток; `shown` — плашка на экране ребёнка («Доставлено»), `read` — нажал «Понял» или вышло время показа (при `showSec` > 0 телефон пишет «Показано»), `expired` — 10 минут ждало ребёнка и погасло («Не доставлено»). Отчёт уходит сразу при смене состояния.

## 5б. Снять запрет на сегодня с телефона (FR-42)

`phone/send kind:"cmd" body: Signed`, `data` — как в разделе 5, плюс необязательное поле `op`:

```json
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":19,"ts":1763490000000,"child":3,"op":"noForbidden"}
```

- `op`: `"extra"` или поля нет — доп. время на `delta` минут (раздел 5); `"noForbidden"` — снять запретные часы на сегодня, `delta` нет (или 0). Неизвестный `op` и `delta` у `noForbidden` — отказ `range`; номер `seq` при этом не тратится (проверка до записи номера, как у длины текста сообщения, раздел 5а). Телефон, который не знает `op`, шлёт команду без него — компьютер понимает её как доп. время.
- Проверки компьютера — как у команды (раздел 5: подпись, `t`, `pc`, `phone`, `ts`), `seq` — в одной нумерации с командами и сообщениями, записывается до применения одной блокировкой службы с ним.
- Применение — то же, что кнопка «Снять запрет на сегодня» окна родителя (R24): запретные часы на сегодня не действуют, экран блокировки запрета снимается, ребёнок видит ту же плашку «Сегодня запретные часы не действуют», в журнале «Миша: запрет на сегодня снят с телефона».
- Ответ `cmdr` — как в разделе 5. `message`: «Запрет на сегодня снят»; запрет уже снят — `ok:true`, «Запрет на сегодня уже снят», журнал второй раз не пишется; сегодня запретных часов нет (ни идущих, ни впереди до полуночи) — `ok:true`, «Сегодня запретных часов нет», ничего не меняется и журнал не пишется. Отчёт в ответе уже несёт `forbid:"cleared"`.

## 5в. Копилка с телефона (FR-44, D-113)

`phone/send kind:"cmd"`, `data` — как в разделе 5, с полем `op`:

```json
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":20,"ts":1763490000000,"child":3,"op":"bankAdd","delta":30}
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":21,"ts":1763490000000,"child":3,"op":"bankClear"}
```

- `bankAdd` — положить `delta` минут в копилку, 1 ≤ `delta` ≤ 600 (одно начисление, как «Начислить» окна, FR-22). Предела баланса нет (D-113). `delta` вне 1…600 — отказ `range`, `seq` не тратится (проверка до записи номера, как в разделе 5б).
- `bankClear` — обнулить копилку ребёнка; `delta` нет (или 0), иначе `range` без траты `seq`.
- Проверки компьютера — как у команды (раздел 5), `seq` — в общей нумерации, записывается до применения одной блокировкой службы с ним.
- Применение — тот же путь службы, что у окна родителя: начисление с причиной «С телефона» (`bonus_ledger.reason`), журнал «Миша: +30 мин в копилку с телефона»; обнуление — запись в историю копилки «Обнулено с телефона», журнал «Миша: копилка обнулена с телефона». Копилка уже пуста — `ok:true`, «Копилка уже пуста», журнал не пишется. «Отменить» у команд с телефона нет.
- Ответ `cmdr` — как в разделе 5. `message`: «Положено 30 минут. В копилке 75 мин» / «Копилка обнулена». Новый баланс — в `report` ответа (`bankMin` ребёнка, раздел 6).
- Тексты телефона: `range` — «Можно от 1 до 600 минут за раз» (телефон проверяет поле сам и такую команду не шлёт).

## 5г. Промокоды с телефона (FR-45, R26)

`phone/send kind:"cmd"`, `data` — как в разделе 5, поле `child` — 0 (промокоды общие), с полем `op`:

| `op` | Поля | Действие |
|---|---|---|
| `promoList` | — | только прочитать список |
| `promoCreate` | `code` (строка), `min` (1…600) | создать код, как «Создать код» окна (R26: после обрезки пробелов A–Z, a–z, 0–9, 3…16 знаков, хранится заглавными) |
| `promoGen` | `count` (1…50), `len` (4…12), `charset` (`"digits"`, `"letters"`, `"mixed"`), `min` (1…600) | «Придумать коды» окна (алфавиты букв без I, O, 0, 1) |
| `promoDelete` | `code` | удалить действующий (неиспользованный) код; удалённый код можно создать заново |

- Все четыре тратят `seq` (чтение тоже: подписанный запрос с номером не даёт серверу повторить его). Неверный вид полей (код не по R26, числа вне пределов, неизвестный `charset`) — `range`, `seq` не тратится; телефон проверяет поля сам теми же правилами и текстами, что окно (8.3.10).
- Применение — те же функции службы, что у окна: `promoCreate` — журнал «Промокод SUMMER на 30 мин создан с телефона»; такой код уже есть (действующий или использованный) — `ok:false`, `error:"promo_exists"` (телефон: «Такой код уже есть, придумайте другой»). `promoGen` — журнал как у окна с припиской «с телефона»; не хватило разных кодов — `promo_gen` («Не получилось придумать столько разных кодов. Увеличьте длину»). `promoDelete` — журнал «Промокод SUMMER на 30 мин удалён с телефона»; кода нет среди действующих (уже удалён или использован) — `not_found` («Этого кода уже нет. Список обновлён»).
- Ответ `cmdr` вместо `report` несёт список промокодов (отчёт о детях в этом ответе не нужен):

```json
{"v":1,"t":"cmdr",…,"ok":true,"message":"Промокод SUMMER на 30 минут готов","codes":["K7PX","M3QA"],
 "promos":{"active":[{"code":"SUMMER","min":30,"createdMs":1763490000000}],
           "used":[{"code":"AB12","min":30,"usedMs":1763480000000,"child":3,"childName":"Миша"}],
           "moreActive":0,"moreUsed":0}}
```

  `codes` — только у `promoGen` (новые коды для «Скопировать все»); `promos` — у всех четырёх при `ok:true` и при `promo_exists`, `not_found` (телефон обновляет список). `active` — по убыванию `createdMs`, `used` — по убыванию `usedMs`; `childName` — имя ребёнка на момент ответа (ребёнок удалён — пусто, телефон пишет «ребёнок удалён»).
- Размер: подписанное тело `pc/reply` — не больше 14 КБ (сервер принимает 16 КБ). Сначала `used` — не больше 50 строк, `active` — не больше 200; не помещается — `used` 20, затем 0; затем `active` вдвое меньше, пока не поместится (до 0). `moreActive`, `moreUsed` — сколько строк не вошло; телефон пишет «Ещё N — в окне родителя на компьютере». `codes` не урезаются (не больше 50 кодов по 12 знаков).
- Телефон хранит последний полученный список и время ответа (`ts`): «данные на HH:MM»; компьютер не на связи — последний список с пометкой «Компьютер не на связи с HH:MM», «Создать», «Придумать», «Удалить» недоступны.

## 5д. Решения о незнакомых программах с телефона (FR-47, R12)

Список ждущих приходит в отчёте (раздел 6, поле `pending`). Решение — `phone/send kind:"cmd"`, `data` — как в разделе 5, `child` — 0, с полем `op`:

```json
{"v":1,"t":"cmd","pc":"<pcId>","phone":"<phoneId>","seq":22,"ts":1763490000000,"child":0,"op":"decide","key":"<id из pending>","cat":"games"}
```

- `cat`: `"games"`, `"study"`, `"other"`, `"blocked"` (как в окне родителя: «Игра», «Учёба», «Прочее», «Запретить»). Другое значение или пустой `key` — `range` без траты `seq`.
- `key` — `id` строки `pending`: первые 16 байт SHA-256 от UTF-8 полного пути программы (ключа решения службы), base64url. Путь в отчёте может быть урезан, поэтому решение идёт по `key`, а не по пути. Компьютер ищет программу среди ждущих с тем же `key`; нет — `ok:false`, `error:"not_found"` (телефон: «Решение уже принято», обновляет отчёт).
- Применение — тот же путь службы, что «Ждут решения» окна родителя: решение действует для всех детей (R12), детям, кто запускал и сейчас на экране, — плашка решения (8.2.4 п. 4), журнал «Решение о «SuperGame» с телефона: игра». «Отменить» у решения с телефона нет.
- Ответ `cmdr` — как в разделе 5, `message`: «SuperGame: игра»; новый отчёт в ответе уже без этой программы в `pending`.

## 6. Отчёт компьютера

`pc/report body: Signed`, `data` = Report:

```json
{"v":1,"t":"report","pc":"<pcId>","phone":"<phoneId>","ts":1763490000000,
 "children":[{"id":3,"name":"Миша","usedSec":3600,"leftSec":1800,"extraMin":15,"blocked":false,
               "forbid":"active","forbidUntilMs":1763496000000,
               "today":{"firstMs":1763463600000,"nowAt":true,"sinceMs":1763485200000,
                        "usedSec":3600,"leftSec":1800,"gamesSec":2700,"studySec":1200,"videoSec":300,
                        "programs":[{"name":"Minecraft","cat":"game","sec":2700}],
                        "sites":[{"name":"youtube.com","cat":"video","sec":300}],
                        "more":{"programs":0,"sites":3},"violations":2,"bypass":1},
               "bankMin":45,"gamesSec":2400,"gamesLimSec":3600,"videoSec":600,"videoLimSec":1800}],
 "pending":[{"id":"<key>","name":"SuperGame","pub":"","path":"C:\\Users\\Misha\\Downloads\\SuperGame\\game.exe",
             "kids":[{"id":3,"tries":3}],"tries":3,"lastMs":1763488000000}],
 "pendingCount":1}
```

- `forbid` — запретные часы ребёнка сегодня (R7, R24), то же, что карточка «Сегодня» окна родителя: `"none"` — сегодня их нет (ни идущих, ни впереди до полуночи), `"ahead"` — будут сегодня, `"active"` — идут сейчас, `"cleared"` — сняты на сегодня. `forbidUntilMs` — только при `active`: конец идущего интервала (телефон пишет «Запретные часы до HH:MM» по своему местному времени). Поля нет — компьютер старой версии: телефон кнопку «Снять запрет на сегодня» не показывает.

- `today` — «Статистика за сегодня» (FR-43): те же числа, что «Итоги» за сегодня в окне родителя (служба считает их одной функцией с окном). `usedSec`, `gamesSec`, `studySec`, `videoSec` — время всего (в счёт лимита), игр, учёбы, видео и соцсетей за сегодня, с; `leftSec` — то же, что у строки ребёнка (−1 — без лимита). `firstMs` — когда ребёнок сегодня впервые сел за компьютер (его сеанс на экране: не отключён и не заблокирован; переживает перезапуск службы в пределах дня; 0 — сегодня не садился); `nowAt` — сидит ли сейчас, `sinceMs` — с какого момента (телефон: «За компьютером с HH:MM» / «Не за компьютером с HH:MM»; после перезапуска службы — с момента запуска). Моменты — UTC мс по часам компьютера. `programs` и `sites` — строки вкладок «Итогов» без «Остального времени»: скрытых и запрещённых нет (как в окне), `name` — то же название, что в окне, не длиннее 60 знаков, `cat` — вкладка: `"game"`, `"study"`, `"video"`, `"other"` (телефон показывает игры отдельным блоком «Во что играл»), `sec` — секунды; по убыванию `sec`; пустой список — `[]`. `violations` — нарушений за сегодня (группа «Нарушения» журнала), `bypass` — из них попыток обхода защиты. Поля нет — компьютер старой версии: телефон экран статистики не показывает.
- `gamesSec`, `videoSec` — потрачено за сегодня на игры и на видео и соцсети, с; `gamesLimSec`, `videoLimSec` — лимит дня на них с доп. временем и промокодами, с (то же, что строка «Игры 40 из 60 мин» окна родителя); −1 — отдельного лимита нет (телефон пишет «Игры 40 мин»). Эти четыре поля есть и в отчёте внутри `cmdr`/`noter`. Поля нет — компьютер старше 0.8.4.
- `bankMin` — баланс копилки ребёнка, мин (то же, что в окне родителя). Поля нет — компьютер старше 0.8.4: телефон не показывает копилку, вкладку «Промокоды» и ждущие программы и пишет «Обновите программу на компьютере до версии 0.8.4».
- `pending` — незнакомые программы, ждущие решения (FR-20, R12), общие для всех детей: `id` — ключ для `decide` (раздел 5д), `name` — название, как в окне (не длиннее 60 знаков), `pub` — издатель (пусто — телефон пишет «Без подписи издателя»), `path` — путь (длиннее 120 знаков — середина заменена на «…»), `kids` — кто из детей запускал и сколько раз, `tries` — попыток всего, `lastMs` — последняя попытка. По убыванию `lastMs`, не больше 10 строк. `pendingCount` — сколько программ ждёт всего (есть, даже когда `pending` урезан до 0). Карточка ребёнка на телефоне: «1 программа ждёт решения» — число строк `pending`, где ребёнок есть в `kids` (урезано — «Есть программы, ждущие решения» по `pendingCount`). Отчёт уходит сразу, когда появляется новая ждущая программа и после решения (из окна или с телефона).
- Размер и урезание: тело запроса `pc/report` целиком — не больше 14 КБ (сервер принимает 16 КБ, раздел 3). Программ на ребёнка — до 20, сайтов — до 10 по убыванию времени; если отчёт больше 14 КБ, списки урезаются у всех детей сразу: не больше 10, затем 5, затем 0 строк в каждом списке; при урезании первыми отбрасываются не игры, игры — последними. `more` — сколько строк не вошло в каждый список. Не поместилось и без списков — `pending` урезается до 3 строк, затем `today` не отправляется, затем `pending` — 0 строк (`pendingCount` остаётся). `today` едет только в отдельном отчёте `pc/report`: в отчёте внутри ответа `cmdr`/`noter` его нет (`pending` и `bankMin` — есть, тело ответа тоже не больше 14 КБ, `pending` урезается так же) (телефон держит `today` из последнего отчёта `pc/report`).
- Отправляется: при включении связи, раз в 60 с, сразу после применённой команды, после привязки, при новой ждущей программе и после решения о программе. `phone` — привязанный телефон (телефон проверяет, что отчёт для него, и отбрасывает отчёт с `ts` старше уже показанного). `leftSec` — то же «осталось», что показывает окно родителя.
- Телефон показывает «На связи», если `serverNowMs − pcLastSeenMs ≤ 60 000` (это только доступность: сервер может её исказить, но не данные), иначе «Компьютер не на связи с HH:MM» (по `pcLastSeenMs`, местное время телефона). Остаток показывается из последнего отчёта с подписью и подписью времени отчёта («данные на HH:MM»).

## 7. Поведение компьютера при обрывах (NFR-16)

- Две горутины на поколение связи: **опрос** (`pc/poll?wait=25`, тайм-аут клиента 35 с) и **отправка** (ответы, отчёты, `pair-code`, `unpair` — очередь заданий, не ждут конца опроса; код привязки появляется ≤ 2 с). Опрос: ошибка сети или 5xx — пауза с экспонентой 1, 2, 4 … 30 с ± 20 %; успешный опрос сбрасывает паузу. Восстановление после возврата сервера — не позже 30 с + 25 с ≤ 60 с.
- 401 с телом `{"error":"unauthorized"}` на опросе (сервер потерял запись компьютера) — повторная регистрация `pc/register`, привязка телефона сбрасывается (телефон увидит «нужно подключить заново»). Иной 401 (прокси, чужой сервис по адресу) — обычная ошибка с паузой: регистрация и привязка не трогаются.
- Связь выключена — контекст поколения отменён (идущий опрос обрывается), `CloseIdleConnections`, ни одного нового запроса (NFR-1). `Stop` не ждёт горутины (служба держит свою блокировку); запись состояния от старого поколения отбрасывается по номеру поколения. Транспорт — без прокси из окружения (`Proxy: nil`).
- 401 на опросе с привязанным телефоном — запись журнала «Телефон отвязан: сервер связи не узнал компьютер» и причина в окне.
- Только HTTPS; `http://` разрешён лишь для `127.0.0.1` и `localhost` в тестовом режиме службы (приёмка S55, S56).
- Сбой связи не трогает учёт, блокировки и стражей; ответы сервера больше 64 КБ, неверный JSON, чужой `pcId` — сообщение отброшено, строка в журнал работы с ограничителем частоты.
