# Памятка ревьюеру PC_block_soft

На что смотреть в этом коде. Пополняется из уроков `docs/LESSONS.md`, когда один класс дефекта встретился 2+ раза. Ревьюер читает эту памятку из BASE (`git show BASE:REVIEW.md`).

1. **Одно число — один источник (PL-83, PL-92).** Время, остаток, копилка и прочие числа, которые видны в окне родителя, окне ребёнка и на телефоне, считает одна функция службы, а представления только форматируют. Красный флаг — число, выведенное из другого («лимит − остаток» вместо потраченного): остаток не бывает меньше 0, и превышение пропадает. Проверка: есть ли тест «превышение лимита», который сверяет все выводы.
2. **Окно и телефон — один путь (PL-83).** Команда с телефона зовёт ту же функцию службы, что кнопка окна, с тем же журналом, плашкой и отчётом.
3. **Сбой чтения не маскируется под ответ (PL-93).** Проверка «уже есть / можно ли», которая не смогла прочитать данные, идёт путём сбоя (окну — «не удалось сохранить», телефону — `stale`).
4. **Проверки не ослабляются в диффе с фиксом (правило 16).** Изменения `*_test.go`, `*.test.ts`, `e2e/*.spec.ts`, `tools/accept/*.ps1`, порогов и workflow — отдельным коммитом `test:` с пунктом ТЗ; косвенную проверку заменяют прямой, а не порогом помягче (PL-94).
5. **Тексты.** Ребёнку на «ты», родителю на «вы», без длинных тире, без технических ошибок; nil-слайсы в ответах — `[]T{}`.
